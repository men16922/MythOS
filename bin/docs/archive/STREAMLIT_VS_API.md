# Streamlit vs API/React

최종 갱신: 2026-06-06

두 플레이 표면은 공존하지만 권위 로직은 하나다.

## Shared Core

- Both call `RuntimeSessionService`.
- PostgreSQL is authoritative state.
- Combat is resolved by `mythos_combat`.
- Narrative is generated by `mythos_narrative`.
- Visual assets use the same visual service/worker/storage path.

## React + FastAPI

Primary web path.

- Server: `src/mythos_api`
- UI: `src/mythos_ui`
- Transport: REST + WebSocket token streaming + async `visual_status`
- Run: `make dev-up`, open `http://localhost:8000`
- Regression: `make test-e2e`

Best for:

- Current product UI work.
- API contract testing.
- Playwright regression.
- Dev tab and infra console links.

## Streamlit

Local demo/debug layer.

- Entry: `streamlit_app.py`
- Run: `make streamlit`, open `http://localhost:8501`
- Combat uses a localhost JSON bridge to avoid per-action iframe remount.

Best for:

- Quick local demo.
- Legacy player/developer view checks.
- Manual runtime smoke outside React.

## Rule

Do not duplicate game orchestration in either frontend. If behavior changes player/loop/combat/save/memory semantics, implement it in shared runtime/service/engine code first and keep UI layers as adapters.
