## 2026-10-12 — Whole-run UI bot (`make playthrough`)

- Until now the browser smoke stopped at the first fight, and the later screens were only checked one at a time. `scripts/dev/ui_playthrough.py` plays a real run through the UI (clicks and keys only; headless, muted, private ports): act intro, opening vignette, five map nodes with events, fights and rewards, then tours shop (buys a card, credits fall), safehouse (heals), treasure (takes the implant) and the final choice into the ending screen, failing on a stuck screen (70 s unchanged) or any console/page error. Result: 0 errors, every screen moved on.
- Found by it: the first fight's coach overlay covers the board until "튜토리얼 건너뛰기" is pressed (works as designed; the bot now skips it like a player). Reachable map nodes pulse, so clicks need `force` (a real click at the node).
- **A whole run now plays through the real UI to a victory ending** (19.7 min, 24 map nodes, three acts, both bosses, shop, safehouses, upgrade pick, chest, final choice → `ending_noble_sacrifice`, 0 console errors; polls: combat 173, reward 66, map 24, event 18, act intro 6). Getting there took bot fixes only, each found from a screenshot of the stuck screen, none a game fault: directional cards need an arrow click; Se-rin's cards grey out once she is down; the reward screen's card-choice overlay and implant pick; the echo row is a plain div (the bot kept clicking it instead of "지도로"); the upgrade pick needs a card selected before confirming; the chest opens on click. The engine's own bots beat the Overseer 40/40 in ~6 turns, so the fights were fine. Honest limit: this is the default assist mode (dev-hook HP top-up, foes worn to 1 HP at fight turn 12/24 so a real card still ends the fight). Unassisted (`--no-god`, careful node choice: safehouse/shop/chest/event before fights) it reaches the end of act 1 in ~5 minutes (8 nodes, 12 reward screens) and loses there, identically on every run (fixed seed) — no unassisted act win. Whether a run is FUN stays the owner's to judge.

## 2026-10-12 — Implant sets (1.x port #19, reopened and done)

- Earlier verdict "needs real-play data" was wrong: the simulator can bound it. `engine/implantSets.ts`: six sets over 39 of the 44 implants (방벽 bulwark, 회복 vitality, 충돌 impact, 교란 signal, 속도 tempo, 거래 trade; boss relics and the two stealth pieces stay out). Two pieces give a small bonus, three a bigger one, built only from passives the engine already reads (max HP, bump damage, trace, credits, shop price, safehouse heal, move, stats — never energy or hand size). Summed live in both `runPassive` and `activePassive`; the max-HP / stat part lands once, when the tier is reached. Reward rolls lean ×1.6 toward a set already held (600-roll test: holding a Bulwark piece offers Bulwark measurably more). Shown as a set card on reward and shop offers (what this pickup would unlock) and in the top-bar tooltip.
- Balance: sets on vs off, same seeds, bot that does not chase sets — mixed 41 → 45 %, greedy 100 → 99 % (noise). Upper bound with a full three-piece set held from the first turn (mixed, 180 runs): first cut +6…+20 pp (signal +20, bulwark/tempo +17, impact +6); tuned (bulwark 4+4 HP, signal −10 %+−10 %, impact 1 then +2 bump) to +10…+16 pp (bulwark +16, signal +16, tempo +14, trade +12, impact +11, vitality +10). Real runs reach three pieces late, so the live effect is a fraction of that.
- `runSim` gained `startImplants`, `run.ts` an exported `grantImplant`, for this kind of experiment. Browser-checked: a reward offering a second Bulwark piece shows "방벽 2/10 · ✓ 최대 HP +4" and taking it raised max HP once.
