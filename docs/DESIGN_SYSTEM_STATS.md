# RPG System: Stats, Traits, and Autonomy Progression

> 이 문서는 Project MythOS의 게임플레이 깊이를 더하기 위한 **스탯, 특성, 그리고 진행도 기반 자율성 시스템** 설계안이다. 
> `docs/GAMEPLAY.md`의 설계를 구체화하며, 플레이어가 관찰자에서 촉매로 진화하는 과정을 기계적으로 지원한다.

최초 작성: 2026-05-30

---

## 1. 시스템 철학: "접속에서 각성으로"

플레이어(Connector)는 처음에는 시스템(MythOS)이 허용한 범위 내에서만 움직일 수 있는 미약한 신호로 시작한다. 하지만 루프를 반복하고 세계의 진실(Lore)에 다가갈수록, 시스템의 제약을 벗어나 더 파격적이고 자율적인 행동을 할 수 있게 된다.

- **낮은 진행도**: 시스템 가드레일 작동. 캐릭터가 위험하거나 비논리적인 행동에 주저함.
- **높은 진행도**: 가드레일 해제. 세계 코드에 직접 개입하거나 시스템의 명령을 명시적으로 거부 가능.

---

## 2. 접속자 5대 핵심 스탯 (Core Stats: 1~10 Scale)

모든 스탯은 최소 1에서 최대 10까지의 범위를 가집니다. AI GM은 이 수치를 기반으로 성공 확률과 서사의 디테일을 결정합니다.

| 스탯명 | 의미 | 활용 및 판정 영향 |
| --- | --- | --- |
| **근력 (Strength)** | 신체적 위력과 지구력 | 물리적 충돌, 장애물 돌파, 직접적인 저항 행동. |
| **연산 (Intelligence)** | 논리적 분석과 해킹 | 시스템 코드 분석, 보안 우회, 복잡한 퍼즐 해결. |
| **공명 (Charisma)** | 사회적 영향력과 감성 | NPC 설득, 군중 선동, 에코(Echo)와의 깊은 교감. |
| **반사 (Agility)** | 반응 속도와 정밀함 | 회피, 은밀한 이동, 찰나의 순간에 내리는 결정. |
| **관측 (Perception)** | 숨겨진 데이터 및 진실 포착 | 단서(Shard) 발견 확률 증가, 시스템 글리치 이면의 진실 감지. |

### 2.1 권장 저장 구조

`PlayerProfile.traits`는 자유 dict이므로, 게임 시스템 값은 아래 구조로 모은다.

```json
{
  "archetype": "비접속자 (Ghost)",
  "stats": {
    "strength": 3,
    "intelligence": 6,
    "charisma": 2,
    "agility": 8,
    "perception": 7
  },
  "attributes": ["[유령 신호]"],
  "autonomy_level": 1,
  "unlocked_traits": []
}
```

## 3. 사이버-신화 속성 (Cyber-Mythic Attributes)

스탯이 수치적인 기반이라면, **속성**은 플레이어의 정체성을 규정하고 특수한 효과나 서사적 선택지를 해금합니다.

| 속성명 | 세계관적 의미 | 게임플레이 효과 |
| --- | --- | --- |
| **[ARK 링크]** | 시스템과의 직접적인 동기화 | ARK 터미널 해킹 시 보너스. 단, 관리자 IX에게 발각될 확률(Tension 상승) 증가. |
| **[유령 신호]** | 존재가 소거된 비접속자 | 잠입 및 추적 회피에 탁월. 대신 일반 시민 NPC와의 상호작용(Charisma) 시 페널티. |
| **[인간찬가]** | 비효율적 의지의 소유자 | 절망적인 상황에서 NPC의 신뢰(Stability)를 얻을 확률 대폭 증가. |
| **[시스템 글리치]** | 존재 자체가 오류인 변수 | 가끔 상식 밖의 행운이 발생. 높은 긴장도(Tension) 상태에서 파괴적인 결과 도출 가능. |
| **[기억의 직공]** | 과거를 엮는 자 | 장면에서 더 정교하고 가치 있는 단서(Narrative Shard)를 추출할 확률 증가. |

## 4. 진행도 기반 자율성 시스템 (Autonomy Progression)

### 4.1 자율성 레벨 (Autonomy Level)
캠페인 진행도(해금된 Lore 수, 총 루프 횟수 등)에 따라 1~5단계로 상승한다.

| 레벨 | 상태 | 플레이어 행동 제약 (가드레일) | UI 표출 (키워드) |
| --- | --- | --- | --- |
| **LV 1** | **수동적 신호** | 시스템의 논리를 벗어난 행동 거부. 위험 감수 불가. | 기본 선택지 위주. |
| **LV 2** | **동조된 관찰자** | 약간의 의문 제기 가능. NPC에 대한 제한적 협력. | 동의, 질문, 회피. |
| **LV 3** | **의식의 균열** | 시스템 명령에 대한 명시적 주저/거부 표현 시작. | 거부, 조사, 보호. |
| **LV 4** | **능동적 변수** | 위험한 도박이나 파괴적 행동 가능. 가드레일 대폭 완화. | 도발, 해킹, 탈취. |
| **LV 5** | **해방된 촉매** | 세계의 물리 법칙 무시, 시스템 코드 직접 수정 시도. | 재작성, 파괴, 각성. |

### 4.2 메커니즘 구현: "심리적 가드레일"

플레이어가 직접 입력(`free-form action`)을 하더라도, 자율성 레벨이 낮으면 AI 캐릭터가 이를 실행하지 못하고 서사적으로 거부한다.

- **System Prompt 주입**: 
  > "현재 당신(캐릭터)의 자율성 레벨은 [N]입니다. 레벨이 낮을 때는 [ARK/시스템]에 대한 근원적인 공포나 데이터적 제약으로 인해 과격하거나 반역적인 행동을 지시받아도 심리적으로 주저하거나, 실행에 옮기지 못하고 안전한 대안을 찾으려 합니다. 서술 시 이러한 내적 갈등을 적극 반영하세요."

- **UI 및 DB 처리**:
  *   **UI (Frontend)**: 자율성 레벨에 맞는 '승인된 키워드'만 힌트로 제공하거나, 입력한 문장이 제약에 걸릴 경우 "시스템 제약으로 인해 신호가 감쇄되었습니다"와 같은 연출 제공.
  *   **DB (Backend)**: 플레이어의 **원문 입력**은 `events` 테이블에 그대로 저장하여 나중에 각성 시 "과거에 당신이 시도했던 의지"로 회상 연출에 활용.

### 4.3 첫 플레이 예외: 튜토리얼 레일

첫 시나리오 `Neo-Seoul: 접속`은 완전한 샌드박스가 아니라 **세계 이벤트 주도형 튜토리얼**로 운영한다.
플레이어는 자유롭게 반응하지만, 장면의 큰 압박과 목표는 시나리오 타임라인이 제공한다.

구현 기준:

- `resources/neo-seoul/scenario.json`의 `tutorial_timeline`을 권위 데이터로 둔다.
- `RuntimeSessionService`는 현재 `turn_index`에 맞는 timeline event를 `NarrativeContext.novelty_notes`에 주입한다.
- AI GM은 플레이어 선택을 반영하되, 해당 턴의 `world_trigger`, `pressure`, `objective`, `required_reveal`을 장면의 중심축으로 삼는다.
- 다음 턴 이벤트는 `TUTORIAL_FORESHADOW_NEXT_EVENT`로 약하게 예고한다.

이 방식은 분기표가 아니라 **월드 클럭**이다. 세계가 먼저 사건을 일으키고, 플레이어는 그 사건에 대한
대응으로 자기 성향을 드러낸다.

### 4.4 Neo-Seoul 튜토리얼 타임라인 요약

| Turn | 이벤트 | 플레이어가 배우는 것 | 주요 압박 |
| --- | --- | --- | --- |
| 0 | 비식별 신호 각성 | 나는 등록되지 않은 신호이며, 시스템은 나를 설명하지 못한다. | 관리망 정정 프로토콜 |
| 1 | 복지 블록 정전과 드론 수색 | 복지점수는 생존 권한이다. | 시민 피해와 추적 |
| 2 | 한강 야시장 거래 | 정보에는 대가가 있고, 최적화 명단은 사람을 지운다. | 명단 확보 경쟁 |
| 3 | 폐기 안드로이드의 꿈 | AI도 폐허의 기억을 품을 수 있다. | 카이 보호/활용 선택 |
| 4 | 관리자 IX의 정중한 봉쇄 | 순응은 안전을 주지만 누군가를 지운다. | 봉쇄와 도덕적 선택 |
| 5 | 잔향으로 남는 선택 | 결과는 Echo로 다음 루프에 남는다. | 종결/붕괴의 의미화 |

## 5. 단계별 세계 변화 (World Evolution)

자율성이 높아질수록 세계도 플레이어의 존재를 더 민감하게 반응하며 변화한다.

1. **1단계 (정적)**: 시스템이 완벽하게 통제하는 무미건조한 세계.
2. **2단계 (경고)**: 플레이어 주변에 미세한 글리치 발생. 관리망의 조사 강화.
3. **3단계 (균열)**: 특정 구역의 물리 법칙이 불안정해짐. NPC들이 플레이어를 인식하기 시작.
4. **4단계 (충돌)**: 대규모 시스템 오류. 관리자 IX가 직접 개입하여 신호 삭제 시도.
5. **5단계 (재탄생)**: 플레이어의 의지에 따라 세계의 테마나 규칙이 근본적으로 변형됨.

## 6. UI/연출 기준

### 6.1 새 게임 인트로

새 루프 시작 직후에는 바로 장면 화면으로 보내지 않고, 한 번의 **세션 인트로 화면**을 보여준다.

목적:

- 첫 플레이가 AI가 무작위로 시작한 장면처럼 보이지 않게 한다.
- 세계 이벤트가 먼저 움직인다는 사실을 설명문이 아니라 경보, 스캔, 정전 지도, 상태 타일로 보여준다.
- 현재 루프의 첫 목표만 짧게 제공한다.
- 첫 진입의 주인공 시그널은 `BLACKOUT` 프레임 안에 배치한다.
- 메인 연결 화면은 `MYTHOS` 키아트 중심으로 유지하고, 주인공 시그널은 세션 인트로로 넘긴다.

데이터 기준:

- `resources/<scenario_id>/scenario.json`의 `ui_copy.session_intro`
- `kicker`, `title`, `body`, `rules`, `objective`, `continue_button` 필드
- `rules`는 번호 달린 규칙 설명이 아니라 작전 콘솔의 상태 타일로 렌더링한다.

연출 기준:

- 텍스트는 최소화한다. 한 화면에서 핵심 상황, 경보 2~3개, 목표 1개를 넘기지 않는다.
- 기본 플레이어 언어는 한국어다. 영어는 `FIRST CONTACT`, `SYS-01`, `CONTROL NET`처럼 짧은 디제틱 UI 코드에만 사용한다.
- 튜토리얼이라는 단어를 플레이어 화면에 노출하지 않는다. 첫 사건의 압박으로 튜토리얼 역할을 수행한다.
- HUD와 메뉴는 SF 작전 콘솔을 참고한다. 버튼은 `진입`, `복귀`, `신호 생성`처럼 행동 중심으로 배치하고, 안정도/추적도/단계는 전투 상황판처럼 즉시 읽혀야 한다.
- 플레이어 HUD에는 위치와 현재 시각, 세션 경과 시간을 함께 표시한다.
- `Codex`는 좌측 메뉴와 우측 본문으로 나눈다. 좌측에는 `내 정보`, `인물 정보`, `인벤토리`, `기억의 별자리`를 배치하고, 우측에는 선택된 정보만 보여준다.

### 6.2 HUD 명명

초기 튜토리얼에서는 원시 시스템 용어를 플레이어용 용어로 번역한다.

| 내부 값 | 플레이어 표현 | 의미 |
| --- | --- | --- |
| `stability` | 안정도 / 은신 안정 | 지하 연대, 피난처, 신뢰 |
| `tension` | 추적도 / 긴장 | 관리망 압박, 드론 수색, 봉쇄 |
| `phase` | 단계 | 접속, 탐색, 교류, 변화, 종결 |

개발자 뷰에는 내부 이름을 유지하되, 플레이어 뷰에는 디제틱 용어를 우선 사용한다.

## 7. 후속 구현 과제

1. **`PlayerProfile.traits` 구조화**: `stats`, `autonomy_level`, `unlocked_traits` 필드 정의.
2. **Director 프롬프트 고도화**: 자율성 레벨과 캐릭터 가드레일을 이해하고 서술하는 GM 로직 테스트.
3. **자율성 UI 연출**: 레벨 상승 시 터미널 해킹/각성 이펙트 추가.
4. **튜토리얼 타임라인 UI화**: 개발자 뷰에서 현재 `tutorial_timeline` event와 다음 event를 표시.
5. **스탯 반영 테스트**: 같은 행동이 스탯/자율성에 따라 다르게 판정되는 provider-level smoke 추가.
