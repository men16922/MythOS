## 2026-07-03 — IX boss no-show ROOT CAUSE: zombie active-combat (not tension-archive)
- Status: Completed (`make check` EXIT=0, **667 tests** green; unpushed). Live cloud (Gemini) repro of the boss-not-firing bug, diagnosed per `/diagnose` with before/after evidence.
- Root cause (CORRECTS the recorded theory): the tension-100 auto-archive was the *symptom*, not the cause. Evidence from the live loop (`loop_99ac4fe6…`): a turn-5 `patrol_ambush` was left `_combat.active=true, outcome=null` (never resolved to a finish) and narrative play continued on top of it (turns 6-26). Because `_begin_requested_combat` is gated on `not CombatService.is_active(loop)` (`session.py`), the zombie combat kept `is_active` permanently True, so the IX climax was silently skipped when the route pointer reached the boss node (rn11, turn ~20). Nothing owned the loop end → tension climbed unguarded to 100 → "Journey's End". Proven by injecting the real serialized `_combat` into a `_commit_scene` repro: boss fired NONE→ix_confrontation once cleared.
- Upstream defect: `choose`/`stream_choose` had no `is_active` guard, so a narrative choice mid-combat generated a story scene and orphaned `_combat.active=true` (how the turn-5 zombie formed). `combat_action` already guarded the inverse.
- Fix (2-layer + invariant): (A) `_redirect_to_active_combat` — `choose`/`stream_choose` re-sync to the live fight instead of generating narrative when combat is active (prevents new zombies + rescues existing ones by forcing the abandoned fight to resolve). (B) a deliberate route-node combat (patrol/boss climax) now supersedes a stale mismatched `_combat` (`_without_combat_state`), so the authored IX climax launches even if a zombie lingers (rescues in-progress loops at the boss). (C) 2 regression tests in `test_session_combat.py` (boss supersedes zombie; narrative choose mid-combat doesn't orphan).
- Verified: focused repro before/after (real route_map + real `_combat`) + local cloud API restarted so the fix is live. The dead loop (`loop_99…`) is `ended`/unsalvageable — needs a fresh playthrough to re-verify live at the boss.
- **Round 2 — loop→combat→boss clean-play (same day, live Gemini QA `loop_52ba…`, `make check` 670 green):** live play exposed a cascade once the boss could fire — (a) **death-spiral**: a soft defeat adds +15 tension → the cooldown's high-pressure bypass re-throws ambient combat every turn, and 0 wins keeps the risk cap at the lowest tier so the same downgraded `patrol_ambush` recurs endlessly ("무슨 선택지든 전투로만"); (b) **boss never terminates**: `_combat_soft_defeat` treats a boss loss as recoverable, so the unwinnable IX fight re-throws forever ("패배해도 계속 이어짐"). Fixes: **boss climax now ENDS the run** — `_is_boss_climax_encounter` + `_resolved_boss_climax_loop` resolve victory→perspective ending / defeat→erasure (with a guaranteed victory fallback), minting an Echo, never a soft defeat; **soft-defeat recovery beat** — `SOFT_DEFEAT_COMBAT_COOLDOWN_SCENES=3` suppresses ambient combat (tension can't bypass) for 3 scenes after any soft defeat (route-node combat unaffected).
