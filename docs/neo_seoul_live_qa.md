# Neo-Seoul Live QA Checklist

최종 갱신: 2026-06-14

이 문서는 `neo-seoul`을 사람이 직접 플레이하면서 판단할 수 있는 항목만 다룬다. 자동 테스트, JSON 검증,
빌드/린트, API 동작 확인은 포함하지 않는다. 완료된 체크 항목은 제거하고, 남은 문제와 다음 플레이에서 볼
항목만 유지한다.

기록 방식:

- `[ ]` 미확인 또는 다음 플레이에서 확인 필요
- `[~]` 일부 개선됨, 장기 플레이 체감 재확인 필요
- `[!]` 문제 있음, 수정 또는 설계 판단 필요

## 0. 2026-06-14 다음 플레이 우선순위

  장기 플레이에서 한강 야시장/Han 회귀가 없는지 재확인한다.
- `[~]` **오프닝 세린 조우 명확화**: fallback 경로는 C-17 지하보도, 정세린의 손, 드론 수색등, 닫히는 셔터가
  보이도록 개선했다. live LLM 경로에서도 같은 명확도가 유지되는지 본다.
- `[~]` **선택지 의미 명확화**: 내부 intent인 `rewrite`가 “서사 개정”처럼 보이면 안 된다. UI에서는
  “시스템 개입”처럼 플레이어 행동 성격이 보이는지 확인한다.
- `[~]` **세린 말투 고정**: 세린이 플레이어에게 존댓말을 쓰지 않고, 건조하고 빠른 반말/명령형을 유지하는가.
- `[~]` **주요 장면 이미지-대본 정합**: 고정 이미지가 있는 주요 장면에서 첫 단락 묘사, 제목, visual brief가
  해당 이미지의 피사체/장소/행동과 어긋나지 않는가.
- `[~]` **전투 패배 후 흐름**: 패배 직후에는 포획/회복 루트가 열리고 즉시 여정 종료되지 않아야 한다. 단,
  이후 추적도나 안정도 누적으로 종료될 때는 종료 이유가 명확히 표시되어야 한다.
- `[~]` **신규 이미지 생성 경로**(2026-06-14 수정): 근본 원인 2가지 규명·수정. ①`make api`/`make streamlit`
  단독은 visual worker를 안 띄움(오직 `make dev-up`이 `visual-worker-bg` 포함) → 테스트는 `make dev-up` 사용.
  ②워커가 enqueue 직후 죽으면 (a) UI placeholder가 "그림 생성 중…"에 영구 고정되고(타임아웃 없음),
  (b) orphaned `pending` 에셋이 이후 모든 enqueue를 차단해 루프 내내 이미지가 안 나왔음.
  수정: UI에 90초 타임아웃→원인 안내 메시지(`App.tsx`), 백엔드 `_has_inflight_asset` stale(>300s) 무시
  가드(`visual_orchestration.py`, 회귀 6건). 남은 것: `make dev-up` 실플레이로 신규 장면 이미지가 실제
  표시되는지 + 워커 중단 시 안내/복구 체감 확인.

## 2. 첫 5분 Hook

- `[!]` 플레이어가 자신이 “비식별 신호”이고 관리자 IX에게 지워질 위험이 있다는 점을 이해한다.
  메모: 위험한 건 알겠는데 왜 위험한지 모르겠다는 피드백이 있었다. -> 묘사 없음

  메모: 선택지가 직관적이지 않고 “무슨 의미인지” 모호했다. -> 조금 나아진듯함
- `[~]` 첫 장면 이후 다음 목표가 명확하다. **결말 경향 명료화(2026-06-14)**: "루트 흐름"의 엔딩 라벨
  (안정적 귀환/시스템 각성/고결한 희생/강제 최적화)이 2단어 추상명뿐이라 "이게 대체 무슨소린데?"였음.
  각 엔딩에 시나리오 narration에서 압축한 **의미 한 줄 글로스** 추가(`RouteNarrative.tsx`, 내부 `condition`은
  비노출). **막 목표 정합(B-part2-i 완료)**: `session_design.chapter_gates`에 phase별 플레이어용 `player_goal`
  추가→serializer `_chapter_goal`(loop.phase 매칭, 내부 flag gate는 비노출)→StoryPanel 목표 스트립에
  "이번 막" 안정 목표를 "현재 목표"(장면별 LLM objective) 위에 상시 표시. **행선지 의미 노출(B-part2-ii
  완료)**: route junction 선택지 라벨을 `{행선지}(으)로 향한다 — {type별 의미}`로 강화(순찰=조용히 이동/조우
  적음, 전투=교전, 시장=보급·거래, 정비=회복 등, `_route_destination_meaning` in `session.py`).

## 3. 선택의 맛

- `[!]` 매 장면 선택지가 서로 다른 가치 판단처럼 보인다: 사람, 증거, 안전, 통제.
  메모: `Perception` 체크 같은 내부식 표현은 플레이어에게 설명 없이 노출되지 않아야 한다.
- `[~]` 선택 후 NPC 태도, 안정도, 추적도, 단서, Codex/Shard 중 하나 이상의 변화가 체감된다.
  메모: 수치 변화 표시는 보이지만, 장기 플레이에서 이야기 변화로 느껴지는지 확인 필요.
- `[~]` 선택 결과가 너무 늦게 오거나 너무 추상적으로 느껴지지 않는다.
  메모: 첫 토큰 지연은 프롬프트 prefill 병목으로 추정된다. 현재 8B 모델 기준 실제 체감 재측정 필요.
- `[!]` 실패/우회 선택도 손해만 주지 않고 다른 정보나 톤을 준다.

## 4. 캐릭터 존재감

- `[!]` 세린은 단순 안내자가 아니라 자기 판단과 감정으로 플레이어를 밀거나 붙잡는다.
  메모: 캐릭터성은 있지만 비슷한 말 반복과 목적 불명 피드백이 있었다. -> 세린의 캐릭터가 어느 순간 사라짐
- `[ ]` 린위에는 거래의 이득과 부채를 동시에 느끼게 한다.
- `[ ]` 카이 RX-09는 보상 장비가 아니라 “기계도 기억할 수 있는가”라는 테마를 연다.
- `[ ]` 관리자 IX는 추상 시스템이 아니라 플레이어 선택을 정정하려는 압력으로 느껴진다.

## 5. 전투 만족감

- `[!]` 전투가 갑자기 끼어든 미니게임이 아니라 추적, 작전 실패, 구출, 동료 보호, 보상 중 하나의 결과로 느껴진다.
- `[ ]` 중반 이후 전투는 target priority, 방어 timing, 이동/거리, 스킬 선택 중 하나를 요구한다.
- `[!]` 승리 후 무엇을 얻었는지 보인다: 통찰, 단서, 아이템, 관계 변화, 다음 루프 정보.
  메모: 통찰/아이템 외 보상 의미가 약하다는 피드백이 있었다.
- `[~]` 패배/도주/손실도 이야기 흐름을 끊지 않고 후속 결과로 이어진다.
  메모: soft defeat가 적용되어 포획/회복 후 계속 진행 가능해야 한다.

## 6. 페이스와 작전 지도

- `[~]` 작전 지도에서 현재 위치, 다음 이동지, 접근 중인 접촉, 이동 위험이 이해된다.
  메모: 선택지가 지도상 순찰/전투/단서와 어떻게 이어지는지 이해하기 어렵다는 피드백이 있었다. -> 개선됨: junction 선택지에 행선지명 + type별 의미(순찰/전투/시장/정비/단서…) 표기(2026-06-14).
- `[!]` 초반 10장면 안에 전투가 강제로 반복되어 서사 진행을 막지 않는다.
- `[~]` 10-15분마다 플레이 감각이 바뀐다: 추격, 은신처, 조사, 거래, 작전, 전투, 동료화, 최종 대면.
  메모: route 노드 anti-stickiness로 같은 노드 안에서도 장면이 전진(골목→배관→서비스 통로→정비)하도록 수정(2026-06-14). 실플레이 체감 재확인 필요.
- `[~]` 같은 톤의 텍스트가 길게 이어져 피로해지지 않는다. 매 장면과 선택마다 이동/상황 변화가 있어야 한다.
  메모: 멀티턴 in-process 검증서 위치 고착(이전 3턴 동일 골목) 해소·반복 문장 0. 추상어 반복도 0(레지스터 reframe).
- `[!]` 전투와 서사 템포가 서로 방해하지 않는다. -> 전투와 서사의 연결성의 여전히 희미함

## 7. 진행도와 재플레이 동기

- `[ ]` Stability/Tension/Temporal Decay/Zone Risk/Clue Matrix가 무엇을 바꾸는지 플레이 중 이해된다.
- `[ ]` 통찰/스킬/해금 보상이 다음 선택이나 전투를 바꿀 것처럼 느껴진다.
- `[~]` SKILL TREE 상태가 이해된다: 해금됨, 습득 가능, 통찰 부족, 선행 필요.
- `[~]` 기록 보관소는 “지난 루프”로 이해되고, 빈 상태일 때도 왜 비어 있는지 알 수 있다.
- `[~]` Echo/Shard가 단순 로그가 아니라 세계가 플레이어 선택을 기억한다는 감각을 준다.
