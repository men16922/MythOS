# Neo-Seoul Live QA Checklist

최종 갱신: 2026-06-08

이 문서는 `neo-seoul`을 사람이 직접 플레이하면서만 판단할 수 있는 항목만 다룬다. 자동 테스트, JSON 검증,
빌드/린트, API 동작 확인은 포함하지 않는다. §0은 이번 사이클에 **우선 확인할 항목**이고, §1~8은 상시 유지하는
전체 체크리스트다.

## 0. 이번 사이클 우선 확인 항목 (2026-06-08)

자동(in-process LLM) QA로 기술 파이프라인은 검증했으나(파싱 예외 0·멈춤 없음·전투 후 재개·패배 종료 정상),
아래는 **사람 플레이로만** 판단 가능한 현재 최우선 확인 항목이다. 실행: `make dev-up` 후 `http://localhost:8000`
(Ollama `ollama serve` 필요, 이미지 끄려면 온보딩에서 fallback/image off).

- `[ ]` **F1 반복 완화 체감(수정 적용됨)**: 같은 장소에 머무는 동안 장면 도입부가 매번 "오존 냄새/배경 묘사"로
  다시 시작하지 않고, 새 사건·대사·행동으로 진입하는가. (자동 14턴 재검증서 반복 0 확인 — 사람 체감 확인 필요)
- `[ ]` **F2 전투 빈도 체감(미수정·관찰 중)**: 초반 10장면 안에 전투가 너무 자주/연속으로 끼어들어 서사를
  끊지 않는가. 전투가 추격·작전 실패의 결과로 납득되는가. (자동 런 변동성 큼 — 튜닝 여부는 사람 판단)
- `[ ]` **전투 후 내러티브 재개 자연스러움**: "계속 ▸" 후 다음 장면이 전투 여파를 반영하며 매끄럽게 잇는가.
- `[ ]` **Tactical Board 신규 UX**: 범례·타일 인스펙터(hover)·전투 시작 학습 목표 배너가 의미 전달에 도움되는가.
- `[ ]` **조우 난이도 곡선**: 튜토리얼(patrol)은 쉽고, 후반(enforcer/wraith)은 target priority/이동/타이밍을 요구하는가.
- `[ ]` **phase 정체 점검**: 장기 진행 시 막/단계 전환이 느껴지는가, 아니면 계속 같은 톤(explore)에 머무는가.

문제 발견 시 `[!]` + 한 줄 메모를 남기고 `docs/PROGRESS_LOG.md`/`docs/NEXT_PLAN.md`에 반영한다.

## 플레이 조건

- 시나리오: `neo-seoul`
- 권장 길이: 30-60분
- 권장 경로: Golden Path 1회, 실패/우회 Path 최소 1회
- 기록 방식: 각 항목을 `[ ]` 미확인, `[x]` 통과, `[!]` 문제 있음으로 표시하고, 문제는 한 줄 메모를 남긴다.

## 1. 첫 5분 Hook

- `[ ]` 부팅/오프닝에서 사용자가 `접속 기동` 또는 시나리오 시작 버튼을 누른 뒤 BGM이 켜진다.
- `[ ]` 시나리오 오프닝을 수락한 뒤에도 BGM이 유지되거나 자동 재시도된다.
- `[ ]` 플레이어가 자신이 "비식별 신호"이고 관리자 IX에게 지워질 위험이 있다는 점을 이해한다.
- `[ ]` 세린을 따라갈 이유가 정보 전달이 아니라 상황, 대사, 위험으로 납득된다.
- `[ ]` 첫 선택이 단순 진행 버튼이 아니라 시민/데이터/안전 중 무엇을 택하는지 느껴진다.

## 2. 선택의 맛

- `[ ]` 매 장면 선택지가 서로 다른 가치 판단처럼 보인다: 사람, 증거, 안전, 통제.
- `[ ]` 선택 후 NPC 태도, 안정도, 추적도, 단서, Codex/Shard 중 하나 이상의 변화가 체감된다.
- `[ ]` 선택 결과가 너무 늦게 오거나 너무 추상적으로 느껴지지 않는다.
- `[ ]` 실패/우회 선택도 손해만 주지 않고 다른 정보나 톤을 준다.

## 3. 캐릭터 존재감

- `[ ]` 세린은 단순 안내자가 아니라 자기 판단과 감정으로 플레이어를 밀거나 붙잡는다.
- `[ ]` 린위에는 거래의 이득과 부채를 동시에 느끼게 한다.
- `[ ]` 카이 RX-09는 보상 장비가 아니라 "기계도 기억할 수 있는가"라는 테마를 연다.
- `[ ]` 관리자 IX는 추상 시스템이 아니라 플레이어 선택을 정정하려는 압력으로 느껴진다.

## 4. 전투 만족감

- `[ ]` Codex/개발 로그 탭에 갔다가 Story로 돌아와도 Tactical Board가 즉시 보인다.
- `[ ]` Tactical Board의 아이콘, 지형, 위험 칸, 적 의도가 무엇을 뜻하는지 플레이 중 이해된다.
- `[ ]` 전투 승리 후 통찰/안정도/추적도/전리품 변화가 전투 결과 패널에서 이해된다.
- `[ ]` 전투가 갑자기 끼어든 미니게임이 아니라 추적, 작전 실패, 구출, 동료 보호, 보상 중 하나의 결과로 느껴진다.
- `[ ]` 첫 전투는 조작과 기본 전술을 배우기에 충분히 쉽다.
- `[ ]` 중반 이후 전투는 target priority, 방어 timing, 이동/거리, 스킬 선택 중 하나를 요구한다.
- `[ ]` 승리 후 무엇을 얻었는지 보인다: 통찰, 단서, 아이템, 관계 변화, 다음 루프 정보.
- `[ ]` 패배/도주/손실도 이야기 흐름을 끊지 않고 후속 결과로 이어진다.

## 5. 페이스

- `[ ]` 작전 지도에서 현재 위치, 다음 이동지, 접근 중인 접촉, 이동 위험이 이해된다.
- `[ ]` 초반 10장면 안에 전투가 강제로 반복되어 서사 진행을 막지 않는다.
- `[ ]` 10-15분마다 플레이 감각이 바뀐다: 추격, 은신처, 조사, 거래, 작전, 전투, 동료화, 최종 대면.
- `[ ]` 같은 톤의 텍스트가 길게 이어져 피로해지지 않는다.
- `[ ]` 전투와 서사 템포가 서로 방해하지 않는다.
- `[ ]` Codex, Run History, 진행도 화면으로 이동할 이유가 자연스럽다.

## 6. 진행도와 재플레이 동기

- `[ ]` Stability/Tension/Temporal Decay/Zone Risk/Clue Matrix가 무엇을 바꾸는지 플레이 중 이해된다.
- `[ ]` 통찰/스킬/해금 보상이 다음 선택이나 전투를 바꿀 것처럼 느껴진다.
- `[ ]` Codex Skill 상태가 이해된다: 해금됨, 습득 가능, 통찰 부족, 선행 필요.
- `[ ]` Run History가 "무슨 일이 있었는지"뿐 아니라 "다음에는 다르게 해볼 이유"를 준다.
- `[ ]` Echo/Shard가 단순 로그가 아니라 세계가 플레이어 선택을 기억한다는 감각을 준다.
