# 계획: 서사 완급 조절 및 품질 고도화 (Narrative Pacing & Polish)

이 문서는 플레이어의 "턴이 너무 빨리 넘어간다"는 피드백과 "서사 연결성 부족" 문제를 해결하기 위한 시스템 개선 계획을 정의한다.

## 1. 문제 진단
- **빠른 페이즈 전환**: 기존 `LoopEngine`은 매 턴 강제로 페이즈를 전진시켜, 서사가 충분히 무르익기 전에 루프가 종료됨.
- **포매팅 노이즈**: AI가 생성한 텍스트에 "지문:", "대사:" 등 게임 엔진용 라벨이 섞여 몰입감을 저해함.
- **루프 간 단절**: 이전 루프의 사건이 파편화된 데이터(Shard)로만 남아, 전체적인 "시나리오의 흐름"을 파악하기 어려움.

## 2. 개선 목표
- AI GM에게 페이즈 전환 주도권을 부여하여 서사 길이를 확장.
- 노벨 게임 스타일의 깔끔한 텍스트 출력.
- 루프 종료 시 '시적 요약'을 생성하여 서사 연속성 확보.

## 3. 세부 실행 계획

### 3.1 서사 완급 조절 (Pacing Control)
- [x] **상태 기계(FSM) 유연화**: `LoopEngine`의 자동 페이즈 전환 로직 제거.
- [x] **AI 주도 전환**: `ScenePayload`에 `requested_next_phase` 필드 추가.
- [ ] **비트 기반 타임라인 (Beat-based Progression)**: `scenario.json`의 `tutorial_timeline`을 `turn` 기준에서 `beat` 기준으로 전환. 하나의 서사 비트에서 여러 턴(3~5턴 이상)을 머물며 상황을 충분히 전개하도록 유도.
- [ ] **목표 플레이 타임 설정**: 1회 루프(세션)당 약 15~20턴(약 10~15분)의 플레이 타임을 목표로 설정.

### 3.2 텍스트 품질 및 연출 (Script Polish)
- [x] **라벨 제거**: "지문:", "대사:" 표기 완전 금지.
- [ ] **노벨류 템플릿**: AI에게 대화와 지문의 구분을 명확히 하되, 라벨 없이 prose만으로 고퀄리티 스크립트를 쓰도록 Few-shot 강화.

### 3.3 서사 연결성 및 요약 (Story Continuity)
- [x] **루프 요약 엔진**: 루프 종료 시 '기록가' 페르소나로 전체 사건 요약 생성.
- [ ] **엔딩 시퀀스 연출**: 루프 종료 시 요약된 내용을 "당신의 발자취"와 같은 형식으로 UI에 아름답게 연출하여 세션의 마무리를 체감하게 함.

## 4. 기대 효과
- 플레이어는 한 루프에서 더 많은 선택과 대화를 경험하게 됨 (플레이 시간 확대).
- 텍스트가 노벨 게임처럼 깔끔해져 가독성이 향상됨.
- 루프가 반복될수록 "내가 이 세계에서 무엇을 해왔는지"에 대한 서사적 줄기가 명확해짐.
