# A2A review → runner-mediated relays (2026-07-12)

Owner asked whether adding an A2A (agent-to-agent) structure to the overnight harness pays off.

## Verdict

**Live A2A (persistent agent-to-agent sessions): no.** It couples engines at runtime, breaking the
harness's core recovery property (one-shot iterations, max loss = 1 iteration; conflicts blocked by
*structure* — AGENTIC.md §0). Live connections are the flakiest part of unattended runs (see the agy
browser-attach incidents), the three engines share no protocol (custom RPC + lifecycle = WS5-scale
work), and every live consult burns both engines' quotas — the binding constraint on 2026-07-11.

**Instead: two new runner-mediated one-shot relays** (same idiom as critic / browser-qa), which
capture most of A2A's value. Both were motivated by concrete same-night failures:

## Relay 1 — image identity judge gate (`OVERNIGHT_IMAGE_JUDGE`, default 1)

- Motivation: the 2026-07-11 cover-sprite batch (`4d5b3be`) passed gate+integrity but had shuffled
  character identities (se-rin got the player design, kai came out human, tae-o female…) — only a
  human caught it, after commit.
- Mechanism (`run.sh`): after gate+critic pass, if the commit adds/modifies images under
  `resources/*/{characters,enemies}/**`, a one-shot **claude vision judge** (plan mode = read-only)
  compares each NEW image against the same character's canon (`-idle`/`-guard` sibling, else
  portrait). Pose differences pass; identity attribute differences (gender/species, hair, mask/
  glasses/scar, signature shield color, different established character) FAIL → revert like
  critic-reject. Fail-open on missing claude CLI/reference/parse (never discards on judge glitch).
  Images with no canon reference are skipped (first-ever art has no baseline).
- Caps: `IMAGE_JUDGE_MAX` (default 8) images judged per iteration.

## Relay 2 — same-night blocker escalation (`OVERNIGHT_ESCALATE`, default 1)

- Motivation: codex burned 2 iterations (~5.5M tokens) on a TS declaration-order error that claude
  fixed in minutes the next session; the item sat `[blocked]` until a human intervened.
- Mechanism (`run.sh`): when a non-claude iteration's commit adds `Blocker`/`[blocked]` lines to
  NEXT_PLAN/PROGRESS_LOG, the runner schedules the NEXT iteration as a one-shot **claude cross-lane
  iteration** (PROMPT.md + an escalation addendum: handle only that blocker item, lane tag waived
  for this iteration). Engine/prompt restored at the next loop top (restore happens at loop top so
  limit/failure `continue` paths can't skip it). Caps: `MAX_ESCALATE` (default 2) per runner run;
  inactive under `--once` (no next iteration).

## Deliberately not built

- Peer-to-peer live messaging/protocol between engines.
- Judge for non-identity aesthetics (stays human review — same boundary as browser-qa's no-revert rule).

Generic-tier port to the `claude-overnight-harness` plugin: pending (do after MythOS soak).
