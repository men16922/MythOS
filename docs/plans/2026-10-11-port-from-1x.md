# Porting candidates from Mythos 1.x (branch `1.0`) to 2.0

Date: 2026-10-11 · Status: **proposal — nothing here is scheduled** · Requested by the owner ("mythos 1.0에서 가져올 만한 기능들을 별도 plan에 정리").

1.x was archived on purpose (`docs/plans/2026-10-10-mythos-2.0.md` §0: LLM-authoritative loops were slow and shapeless). So this list is deliberately critical: only things that fit 2.0 — a ~30-minute tactics deck-builder where the AI GM **never blocks play** and every AI line has an authored fallback. Read 1.x source with `git show 1.0:<path>`; do not check the branch out into the working tree.

**How this was made**: a read-only survey of `1.0` (docs, `src/mythos_runtime`, `src/mythos_narrative`, `src/mythos_ui`, `resources/neo-seoul`, `scripts`, `tests`), then spot-checked here: every path below was confirmed to exist on `1.0`, and the 2.0-side claims (e.g. `mythos_v2/llm.py` records no token usage) were checked against the current tree. Effort is S ≤ ½ day, M ≈ 1–3 days, L > 3 days, in 2.0 terms. Priority is *value to 2.0 players or operators*, adjusted for what 2.0 already has.

## A. Narrative / AI GM

### 1. GM naming and register guard — high, S — **DONE 2026-10-11** (`talk.absent_companion_named` + `drop_polite_sentences` on narration, companion chat and IX; naming rule added to the narrate prompt; 한 is only checked in English)
- **1.x**: `resources/neo-seoul/directives/naming.md` (+ `.en`), `docs/PROMPT_LAYER.md`, `tests/test_directive_locale_parity.py`. Rules: fixed proper-noun spelling; each companion's speech register (e.g. Se-rin never speaks politely); a character may be named only when present; the model may not invent score/currency nouns. This was the failure mode the 1.x judge rubric tracked most.
- **2.0 gap (checked)**: `talk.py` already has `_invents_names` (a quoted name the context never gave is rejected in companion replies), but `gm.py` narration (`clean_line` / `clean_narration`) guards only language, length and quotes, and neither path rejects a line that names a companion who is *not in the party*. The register rules (who never speaks politely) are not in the prompts either.
- **Plan**: (a) extend the existing guard into a shared post-filter for narration and chat: reject a line naming a companion absent from `context.party` (and unknown proper nouns outside a small allow-list) → authored fallback; (b) one short naming/register block in the prompts, sourced from the 1.x file. Tests in `tests/test_v2_gm.py` / `test_v2_talk.py`.
- **Risk**: false rejects only cost an authored line. Counted in the new `v2_gm_usage` table as outcome `rejected`, so the rate is visible.

### 2. Stat inner voices — high, S — **DONE 2026-10-11** (`content/statVoices.ts`, shown under the outcome after the text finishes typing)
- **1.x**: `directives/stat_voices.md` (5 personas), `src/mythos_ui/src/statVoice.ts`, `scenario_context.py`.
- **2.0 fit**: events already roll STR/AGI/INT/CHA/OBS checks. On a check, show one authored line from the relevant stat's voice (success/failure/low-stat variants). No LLM, no balance effect — it gives the five stats a personality (Disco-Elysium-style).
- **Plan**: `content/statVoices.ts` (5 voices × ~3 lines × KO/EN, narrative-register rule: concrete, not abstract SF), shown in `EventScreen` under the outcome text; a narrative test for coverage and length.
- **Owner**: reads the 15 lines once for tone.

### 7. Twist bank → gated reveal events — medium, S–M — **CLOSED 2026-10-11, nothing to port** (all three twists already exist in 2.0: Se-rin's hidden line = `a3_serin_inside_line`; the grid collects rather than deletes = `a3_data_incinerator` + `lore_data_incinerator`; the player's earlier self = `a3_blank_in_list`, `a3_other_pod`, `lore_previous_self`)
- **1.x**: `src/mythos_runtime/twists.py`, `scenario.json` `twist_bank`: three authored reversals (Se-rin's duality, the grid's true purpose, a clue to the player's identity); at most one per loop; gated on flags/relationship; paired with sting + glitch cues.
- **2.0 fit**: port as gated Act 2/3 events that reuse the existing stings. **Check first** against the companion arcs (`eventsArcs.ts`, `eventsMore.ts`) and `lore_blank_line` / `lore_previous_self` — two of the three overlap existing threads. Probably port one or two, not all.

### 8. NPC agenda lines — medium, S — **DONE 2026-10-11** (`talk.AGENDAS`, one quiet inner goal per companion in both languages, injected into the companion prompt)
- **1.x**: `scenario.json` `npc_agendas` (goal + behaviour rules per companion/IX), `npc_agenda_allowed_subjects`.
- **2.0 fit**: add 1–2 lines per character to the `talk.py` persona block so companion chat and IX comms stay in character between events. Keep it short — GM replies are 1–3 sentences.

### 9. Story-bible text — medium, S — **DONE 2026-10-11** (mined for the one thing 2.0 lacked: IX's mirror, `content/ixMirror.ts`, shown on `a3_ix_offer`; the character/location entries duplicate existing 2.0 lore)
- **1.x**: `resources/neo-seoul/story_bible/bible.json` (+ `.en`): 36 entries (branch 11, character 5, act 4, location 4, mystery 2, antagonist 2, archive 2), `src/mythos_narrative/codex.py`.
- **2.0 fit**: **mine the text, do not port the selector** (`story_bible.py` priority/token-budget machinery serves long prompts; 2.0 prompts are tiny). Use it to enrich the 23 lore entries and the GM `context` facts. Reconcile with 2.0 canon first.

### 14. Controlled generation for improvise — low-medium, S — **ALREADY IN 2.0** (`GeminiTextLLM` sends `response_mime_type=application/json` + `response_schema` via `config.to_gemini_schema` whenever a JSON schema is passed; the Ollama path uses `response_format: json_object`)
- **1.x**: `gemini_provider.py` used `response_schema` (`SCENE_JSON_SCHEMA`).
- **2.0 gap**: `gm.parse_json_object` parses by hand and falls back on any miss. A schema guarantees shape and should cut fallbacks. Ties to the SDK/model version; measure the fallback rate in the dashboard before and after.

### 17. Deterministic run ledger — low-medium, S — **CLOSED, no gap** (the client already sends the last five run-log notes, party, act and archetype with every companion/IX/narrate call, and the new naming guard checks replies against that same context; a separate ledger would duplicate it)
- **1.x**: `session_memory.py` — a bounded `_beats` list (≤ 40) and a rolling synopsis built without an LLM.
- **2.0**: the client already sends recent log notes to `talk`. Formalise only if the dashboard shows chat/IX lines losing the thread; otherwise skip.

### 18. Prompts as KO/EN markdown with a parity test — low, M — **NOT PORTED** (a refactor with no player-visible gain; the naming rule and agendas were added to the inline prompts instead)
- `gm.py` (~1.2k lines) and `talk.py` (~1.1k lines) hold prompts inline. Moving prose to files lets tone be tuned without touching code, but it is a refactor with no player-visible gain. Do it only alongside #1/#8 if the prompt blocks grow.

## B. Gameplay / meta

### 5. Daily-seed mutators — medium, S–M — **DONE 2026-10-11** (`engine/mutators.ts`: 8 mutators, one per KST day; shown on the daily setup screen and as a HUD chip)
- **1.x**: `src/mythos_runtime/loop_modifiers.py`, `scenario.json` `loop_modifiers` (patrol surge, market boom, signal jam), seed-picked and shown as a banner.
- **2.0 fit**: attach one seeded mutator to the **daily seed** only (same for everyone, so leaderboard scores stay comparable): e.g. shop prices −, Trace gain +1/node, elite rate +. Variety for a board players visit daily.
- **Plan**: mutator list in `content/`, applied in `engine/daily.ts` / `run.ts`; verify with `simulateRun` on fixed seed blocks (the lessons: ≥3 blocks) that none breaks Paradox-0 daily balance; show the banner on the daily setup screen.

### 13. Companion mastery — low-medium, M — **DONE 2026-10-12** (`MetaProfile.companionWins`; mastery I at 2 shared victories = signature card starts upgraded, II at 5 = starts at bond 1; never on a daily; badge + tooltip on the starting-companion picker)
- **1.x**: `companion_growth.py`; upgrades gated by meta counters (`total_combats_won >= 6`).
- **2.0**: bond tiers already unlock companion cards/passives. Mastery would add a replay reason (e.g. N wins together → signature card upgraded). Needs per-companion counters in `meta.ts` and a design decision on whether it overlaps the Archive threads.

### 19. Implant tag set bonuses — low, M — **DONE 2026-10-12** (`engine/implantSets.ts`: six sets over 39 implants, tiers at 2 and 3 pieces built only from existing passives; reward rolls lean ×1.6 toward a held set; set name, progress and tier bonuses shown on rewards, in the shop and in the top-bar tooltip). Earlier note that this "needs real-play data" was wrong: the sim can bound it, see PROGRESS_LOG
- **1.x**: `boons.py` — two or more boons with the same tag grant a bonus. 2.0 has 44 implants; set bonuses reward commitment but add a whole balance surface. Not before real-play data.

### 12. Status-stacking verification vs bosses — low-medium, S — **DONE 2026-10-11** (verified, no cap needed: a burn-heavy deck (8 burn cards) shortens bosses 25–30 % but IX mixed win does not rise (65 → 61 %); max single burn is 4 and burn decays by 1 per turn)

- **2.0**: do not port code. Use it as a checklist: can burn/mark/weak stacking trivialise Haetae, Echo Eater or IX? Verify with the sim / per-encounter telemetry (the method used for the Incinerator in `PROGRESS_LOG`).

## Looked at and recommended NOT to port

- Streamlit demo, FastAPI `/api/v1` loops/WebSocket, `RuntimeSessionService`, Postgres progression tables — 2.0 is browser-side TS with a thin server mirror.
- The LLM-authoritative loop (`mythos_narrative` director, dual 8B+3B models, `parser.py` repair, `mythos_loop/validator.py`) — 2.0 keeps the AI off the critical path.
- Route DAG/growth, `encounter_map.py`, `mapgrid.py`, the whole 1.x combat engine (`mythos_combat/*`, `combat_server.py`) — 2.0 has `map.ts` and its own grid combat.
- `ending_resolver.py` AST evaluator and Stability/Tension/Insight scoring — 2.0 endings are chosen after IX.
- `echoes.py` inscription — overlaps 2.0's memory threads.
- `NoveltyController` (`variation.py`) — built for 40-turn narrative repetition; not 2.0's shape.
- Visual generation orchestration (`visual_*`, FLUX/mflux, `postprocess.py`) — 2.0 art is pre-generated and static.
- Invite-key gating and per-player loop caps (`invite.py`, `limits.py`, `InviteGate.tsx`) — replaced by Firebase sign-in and `ratelimit.py`.
- Save-slot UI and run history (`save_load.py`, `SaveLoadModal.tsx`) — 2.0 already has save blobs and run history.
- Overnight harness / dev-graph / engineering docs — already carried over or process-only.
- Serving-research experiments (`experiments/*`, `engine_options.py`) — not part of the shipped game.
- Glass Library scenario — held in 1.x, not part of 2.0.
- Legacy BGM `.wav` files and the empty voice-id map — 2.0 has its own m4a score.
