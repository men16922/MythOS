## 1. 한 줄 평가

Argon은 **양(콘텐츠·시스템)을 빠르게 많이 넣었다**(5스탯 전투, 회피/치명타, 출혈/부식, 적 12·카드 14·이벤트 9·임플란트 4·변칙 4, BGM 10곡, 쇼케이스 영상·Devpost 원고). 게이트(`make check`)는 통과했다. 하지만 **게임 전체에 미치는 영향은 측정하지 않았다**:
난이도가 오너가 고른 값(혼합 봇 승률 ~31%)에서 **~75%로 무너졌는데**, 문서에는 이전 측정값(30.9%)이 그대로 남아 있었다.

| 축 | 점수 | 근거 |
| --- | --- | --- |
| 기능 구현량 | A | 엔진/콘텐츠/UI/영상/문서를 하루에 끝냄 |
| 코드 정확성 | B− | 게이트 통과. 하지만 규칙 텍스트와 실제 동작이 어긋남(아래 §2.2) |
| 구조/유지보수 | C | 스탯 문턱값이 엔진·HUD에 중복, 변칙 규칙이 문자열 분기로 흩어짐, 인카운터 id·적 id 하드코딩, 죽은 코드(`world_echo_throne`) |
| 밸런스 검증 | D | 승률 31%→75%(greedy 100%)인데 미측정, 문서 수치는 이전 값 |

## 2. 발견 사항 (증거)

### 2.1 밸런스 붕괴 — 실측 (P0, 혼합 봇, 120~150판 블록)

| 시점 | 혼합 승률 | 비고 |
| --- | --- | --- |
| `0699ace` (Argon 이전, 오너 HP 34/32/36 선택) | **30.8%** | 고스트 35 · 밀수꾼 10 · 수집가 46 |
| `1f97f84` (5스탯·회피·치명타·DoT) | 61.7% | +31p |
| `491f071` (볼륨 확장, 지도 8행) | **~75%** (70.8–77.5), greedy **100%** | +13p |

어블레이션: 스탯 보너스를 전부 끄면 51.7%. 지도 7행으로 되돌리면 **−16p**. 한 막에 노드가 하나 늘면 덱이 눈덩이처럼 커진다. 그래서 원인 하나를 지목할 수는 없고, "시스템 +25p, 볼륨 +20p"가 겹친 결과다.

### 2.2 텍스트 ↔ 동작 불일치 (숨은 규칙)

- `overclocked_grid`: 문구는 "전투당 첫 전술 환급"인데 코드는 **매 턴** 환급했고, 문구에 없는 **DoT ×1.5**도 숨어 있었다.
- `magnetic_storm`: 문구에 없는 **충돌 +2, 밀치기 +1**이 숨어 있었다.
- `acid_rain`: 문구는 "모든 적 부식 2"인데 코드는 **앞 2명만** 적용했고, 문구에 없는 **위험 지대 2배**도 있었다.
- `ripper_hound`: 문구는 "이동 칸마다 추가 피해"인데 실제로는 이동 1회당 한 번이다.
- 치명타/회피 팝업이 한국어 모드에서도 영어(`CRIT!`/`EVADE`)로 나왔다.
- 출혈·부식 피해 숫자가 화상·감전과 같은 색이라 세 DoT를 구분할 수 없었다.
- 변칙 테이블 순서를 바꾸고 항목을 추가해서, 배포 당일 **오늘의 데일리 변칙이 바뀌었다**(`hash % length`). 이미 배포됐으므로 되돌리면 한 번 더 바뀐다 → 순서는 그대로 두고 기록만 남긴다.

### 2.3 구조

- 스탯 문턱값이 `effects.ts` 헬퍼 5개, `combat.ts` 인라인, `TopBar.tsx` 툴팁에 **세 번 중복**돼 있어서, 하나를 고치면 HUD가 거짓말을 하게 되는 구조였다.
- `startCombat`이 변칙 id·월드 잔향 플래그·인카운터 id(`a3_boss_ix`)를 문자열로 분기했다. `world_echo_throne`은 어디서도 설정되지 않는다(죽은 코드).
- `combatSim.moveInPlace`가 질주 회피 로직을 복붙하고 있었다.

## 3. 이번 세션에서 한 일 (Claude Opus 5.5)

**리팩토링 (동작 보존, 단일 출처)**
- `engine/statPerks.ts` 신설: 5스탯 → 전투 보너스 표 하나. 엔진(`perksOf`)과 HUD 툴팁이 같은 함수를 읽는다.
- `MutatorDef.combat`(개전 상태·위험 지대 배수·밀치기 보너스·전술 환급)을 데이터로 옮기고 `mutatorCombat()`로 읽게 했다. 문자열 분기를 제거하고, 모든 규칙을 boon/burden 문구에 명시했다.
- `WORLD_ECHOES` 데이터 테이블(`legacy.ts`): 이름·설명·크레딧·유대·전투 효과를 담았다. SetupScreen 하드코딩 문구와 인카운터 id 분기, 죽은 `world_echo_throne`을 제거했다.
- 개전 처리 `applyOpeningPerks()` 하나로 통합하고, `sprintEvade()`/`hazardDamage()`를 공유하게 했다(시뮬레이터 복붙 제거).
- 기본 적 강도를 엔진 상수가 아니라 **콘텐츠 데이터**(`CONTENT.tuning`)로 두었다 — "데이터는 content에만" 규칙을 따르고, 테스트 픽스처는 원래 수치 그대로 유지된다.

**밸런스 (오너 의도 복원 + 피로도 감소)**
- 지도를 **8행에서 7행으로 환원**했다(막당 8층, 한 판 24층). UX-first·저피로 원칙과 맞고, 혼자서 −16p 효과다.
- 스탯 보너스 문턱을 +1 올렸다(시작 스탯이 아니라 성장으로 얻게).
- `CONTENT.tuning`: 적 HP +12%, 엘리트·보스 +20%, 모든 적 공격 +1(예고 수치에 그대로 표시). HP 패딩보다 피해를 먼저 올렸다(HP +10%/엘리트 +25%/2막부터 +1 안은 보스전이 10.2턴으로 늘어서 기각).
- 출혈은 **이동할 때만** 피해를 준다(가만히 있으면 절반으로 응고). 화상=시간, 출혈=움직임, 부식=장갑으로 정체성을 분리했다.
- 밀수꾼: HP를 32에서 35로, `system_hack` 드로우 1, 시작 임플란트 `overclocked_deck`에 **매 턴 방어막 2**를 추가했다(지속 방어가 없던 게 원인. 밀수꾼 단독 ~32% → ~46%).

**수정**: 위 §2.2 불일치를 전부 고쳤다(변칙 문구·코드 일치, 산성비는 모든 적 적용, 리퍼 하운드 문구, 치명타/회피 팝업 한국어화, 출혈=진홍·부식=산성 녹색 숫자 색).

**아트 (Codex image, GCP 과금 0)**: 재사용 자리를 전부 고유 아트로 교체했다 — 보스 키아트 3, 보스 스프라이트 3세트, 카드 14, 임플란트 4, 이벤트 9, 적 스프라이트 9세트(총 Codex 68콜). 텍스트 유무는 눈으로 확인했다(`qa_text.py`는 Gemini라 미실행).

## 4. S랭크 기준과 남은 계획

"S랭크" = 아래 7개 축을 모두 충족하는 상태. 현재 판정은 괄호 안.

1. **규칙 가시성** — 숨은 규칙 0, 모든 수치가 툴팁·문구와 일치. (**A** — 이번에 정리)
2. **긴장 곡선** — P0 혼합 35–45%, 사망이 막별로 분산, 엘리트가 "고를 만한 위험". (**B+** — 승률은 맞췄다. 엘리트 패배율 ~3%로 여전히 안전하다. 엘리트 피해 +1·+2 실험도 패배율을 못 움직였다 → 기믹 설계 문제)
3. **빌드 다양성** — 아키타입 승률 격차 ≤ 10p. (**B−** — 37p에서 17p로 줄었다. 밀수꾼은 Argon 이전부터 10%였다. 해킹 보상 설계가 남았다)
4. **난이도 사다리** — Paradox 1→5가 한 단계씩 고르게 어려워짐. (**A−** — 46 → 31 → 27 → 16)
5. **저피로** — 일반전 4–5턴, 보스 ≤ 9턴, 한 판 ≤ 45분. (**B** — 한 판 24층으로 줄었지만 보스 10턴)
6. **고유 아트/연출** — 재사용 0, DoT·치명타·회피 피드백 구분. (**A−** — 아트 교체 완료, UI에서 실물 검수 필요)
7. **사람의 재미 판정** — 오너 펀 체크. (**미판정** — `docs/test/mythos2_fun_check.md`)

**운영 규칙 (제안)**
1. 엔진·밸런스에 닿는 변경은 **`simulateRun` 3블록 수치**를 커밋 메시지나 PROGRESS_LOG에 붙인다. 숫자가 없으면 "미측정"이라고 적는다.
2. 플레이어에게 보이는 규칙 문구는 같은 커밋에서 테스트로 묶는다(예: 변칙의 `combat` 키 ↔ 문구).
3. "아트 100%"는 **고유 파일 100%**를 뜻한다. 재사용은 플레이스홀더로 표시하고 Astra에게 넘긴다.
4. 한 커밋은 한 주제로, 접두사(`feat`/`fix`/`balance`/`refactor`/`art`/`docs`)를 붙인다.
