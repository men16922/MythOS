# 다음 업데이트 계획 — "청구서"

작성일: 2026-10-31 · 상태: **제안, 오너 승인 전. 착수는 오너 판정 뒤** · 근거: `docs/plans/2026-10-30-next-content-expansion-plan.md`의 W1~W4, `docs/test/mythos2_fun_check.md`, 현재 코드 대조.

## 0. 결론

**다음 업데이트는 W1을 줄인 "청구서"다. 앞에서 한 선택이 후반에 장면으로 돌아온다.** 새 시스템, 새 카드, 새 구역 없이 기존 사건, 플래그, 선택 축으로 만든다.

- 이유: 지금 카드 176, 적 87, 조우 106, 임플란트 62, 사건 149, 듀오 12, 진화 12로 양은 충분하다. 재미 기준 세 가지(판단, 장면, 발견) 중 "내 선택이 나를 따라온다"는 장면이 아직 약하다. 1.0의 후반 갈래 5개 중 2.0에 있는 것은 `lin_yue_debt` 하나뿐이다.
- 범위: 후반 청구 장면 10개, 엔딩 잔향 7개, 딥 시그널 첫 진입 연출. 신규 그림은 5장 이내.
- 선행 조건: 오너 판정. "문제"가 나오면 그 수정이 먼저고, 청구서는 뒤로 밀린다.
- 공모전이 공고되면 W2가 청구서 앞으로 올 수 있다(§6).

## 2. 2단계 — 프로토타입 (그림 없이, 한 갈래만)

**린위에 빚 한 갈래의 청구 장면 2개만 만들어 오너가 판단한다.** 봇은 재미를 재지 못하기 때문이다.

이 갈래를 고른 이유는 플래그 `lin_yue_debt`가 이미 있고(`content/events.ts:822`에서 설정, `:1392`에서 청산 선택지), 빚을 갚지 않은 경우의 후반 장면만 비어 있기 때문이다.

- 장면 1: 표준 런 3막, 장부가 청구된다.
- 장면 2: 딥 시그널 구간, 끝까지 갚지 않은 경우의 결과.
- **통과 기준:** 오너가 "이 선택이 돌아왔다"고 느끼는가. 아니면 형식을 바꾸고, 나머지 네 갈래를 만들지 않는다.

## 3. 3단계 — 본 제작

### A. 후반 청구 나머지 네 갈래 (M)

갈래마다 표준 런 1장면, 딥 시그널 1장면. 조건이 맞지 않으면 일반 사건으로 대체되어 빈 노드가 없다. 후보 신호는 이름 기준이라 착수 때 의미를 읽고 확정한다.

| 갈래 | 후보 신호 (현재 코드) | 돌아오는 결과 |
| --- | --- | --- |
| 세린 불신 | `serin_signal`, `serin_line`, `saved_citizen` 없음 | 세린이 협력은 하지만 거리를 둔다 |
| 카이 미각성 | `kai_found`, `kai_woken`, `kai_clue` | 후반 단서와 감정선이 달라진다 |
| 강행 돌파 | 추적도, `dominance` 축 | 전투 보상은 늘고 조용한 선택지가 좁아진다 |
| 증거 우선 | `insight` 축, `saved_citizen` 없음 | 다시 쓰기 쪽이 강해지고 세린·시민 관계가 약해진다 |

새 효과 종류는 만들지 않는다. 기존 `requires`, `flag`, `axis`로 표현한다. 플래그를 늘려야 하면 앞쪽 사건에 표시만 추가한다.

### B. 엔딩 잔향 3 → 10 (S~M)

엔딩은 10종, `WORLD_ECHOES`는 3종이다(`engine/legacy.ts`). 7종을 더해 어떤 엔딩을 봐도 다음 판 첫 화면이나 세계의 작은 부분이 달라지게 한다. 대부분 문장과 화면 변화로 하고, 수치 효과는 있어도 작게 한다.

### C. 딥 시그널 첫 진입 연출 (S)

브랜치 `1.0`의 `boot_lines`, `signal_lines`(`resources/neo-seoul/scenario.json:1845`, `:1837`)로 짧은 부팅 화면을 만든다. 2.0에는 없다. 첫 진입에 한 번만 나오고 클릭으로 넘긴다.

### D. 상태 이상 보스 재측정 (S, 측정만)

2026-10-11의 "보스 스택 상한 불필요" 판정은 출혈과 부식이 생기기 전 결과다. 다시 재서 필요할 때만 상한을 넣는다. 콘텐츠를 건드리지 않아 측정 자체는 대기 중에도 할 수 있다.

## 5. 제약과 검증

**밸런스.** 표준 런 혼합 봇이 202/450 = 44.9 %로 밴드 35~45 %의 상단에 있다. 청구 장면은 보상을 순증시키면 안 된다. 얻는 만큼 잃게 만든다. 착수 전 기준 시드에서 기준선을 다시 잰다.

**사건 풀 변화.** 빈 효과 카드를 넣어도 승률이 움직인 전례가 있다(`docs/LESSONS.md` 2026-10-27). 사건도 같은 슬롯의 무효과 사건과 같은 시드로 A/B 비교한다.

**재현성.** 청구 장면은 데일리와 리플레이 검증을 깨면 안 된다. 잔향과 부팅 연출은 데일리에서 끈다.

**이전 저장.** 진행 중인 판을 새 버전에서 불러와 깨지지 않는지 확인한다.

| 묶음 | 통과 기준 |
| --- | --- |
| A 청구 장면 | 갈래별 강제 시드로 실제 UI 확인, 플래그 도달성 테스트, 한국어·영어 문구, 3블록 시뮬 밴드 유지 |
| B 잔향 | 모든 엔딩에 잔향이 있음을 테스트로 보장, 수치 효과는 시뮬 A/B |
| C 부팅 | 첫 진입에 한 번만 표시, 넘기기 가능, 데스크톱 + 390 px 확인 |
| D 측정 | 수치를 `PROGRESS_LOG.md`에 기록, 상한을 넣으면 시뮬 A/B |
| 전체 | `make check`, `make test-e2e-v2`, `make playthrough-quick`, `gameplay-qa` |
| 배포 | `make deploy-preview` → `make verify-preview` → `make url-smoke URL=<프리뷰 주소>` → 오너 승격 |

담당: 설계, 엔진, 밸런스, 게이트는 Claude. 장면 초안과 QA는 Argon, 문체 검수와 그림은 Astra. 새 그림은 Codex image만 쓴다. 음악은 기존 루프를 재사용한다.
