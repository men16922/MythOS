# 플레이스토어 출시 실행 계획

기준일: 2026-11-05 · 기존 결정: `docs/DECISIONS.md` 2026-10-18 · 실무 문서: `docs/play-store.md`, `docs/android.md`, `docs/online.md`

## 1. 출시 방향과 승인 범위

기존 상품안은 **무료 다운로드, 광고 없음, 선택 구독 Signal+ 월 ₩3,900**이다. 앱 자체를 유료로 판매하는 안과 혼동하지 않는다. 10월 18일의 Play 출시·Signal+ 보류는 아직 해제되지 않았다. 이번 요청은 실행 계획 정리이며, 계정 결제·테스터 초대·스토어 업로드·공개 출시·구독 판매를 시작했다는 뜻은 아니다.

**권고 순서: 무료 앱으로 내부/비공개 테스트 → 무료 정식 출시 → Signal+ 검증 후 별도 업데이트.** 구독 상품 준비를 무료 앱 테스트의 선행 조건으로 두지 않는다. 이 순서는 계획의 기본 제안이며, 실제 재개 시 오너가 첫 출시 범위와 국가를 확정한다. 권고 초기 국가는 한국, 언어는 한국어·영어다. 글로벌 확대는 영문 검수와 운영 지표를 보고 결정한다.

| 구분 | 무료 1차 출시 | 후속 Signal+ 출시 |
| --- | --- | --- |
| 게임 | 현재 기본/Deep/Outside/Sea 콘텐츠, 오프라인 플레이, 광고 없음 | 동일한 전투·콘텐츠 규칙 유지 |
| 온라인 | 선택 Google 로그인, 클라우드 저장·일일 순위·허용량 내 AI | 더 큰 AI 허용량; 월 ₩3,900은 기존안이며 판매 전 상품 화면에서 최종 확인 |
| CRPG | 현재 `SetupScreen.tsx`는 일반 런의 전체 CRPG를 개방한다. 기존 문구의 “Signal+만 구역을 연다”는 삭제 | 이미 무료인 구역을 다시 잠그는 변경은 이 계획에 포함하지 않음 |
| 결제 UI | 구매 불가 버튼·구독 잠금·오해를 부르는 업셀 제거/숨김 여부를 Android에서 검증 | 상품·가격·자동 갱신·취소·복원 안내와 실결제 검증 후 활성화 |
| 제외 | 숨겨진 Chronicle을 정식 기능으로 홍보하지 않음; Play Games Services·유료 음성 생성은 후순위 | 무제한 AI 약속 금지; 결제 상품 없이 구독 가능하다고 안내하지 않음 |

현재 Google 문서는 신규/업데이트 target API 36을 요구한다. 소스 설정은 일치하지만, 이것만으로 배포 준비 완료는 아니다. [대상 API 정책](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)

현재 크기 기준은 **base module의 압축 다운로드 500MB**이며 AAB 파일 자체의 바이트 수와 다르다. 200MB 초과는 모바일 데이터 설치 안내의 기준이다. bundletool은 근사치이고 최종 판정은 Console 측정이다. [앱 크기 한도](https://support.google.com/googleplay/android-developer/answer/9859372?hl=en)

## 3. 실행 순서와 담당자

D0는 **오너가 출시 준비 재개를 지시한 날**이다. 아래 기간은 작업 순서용 가정이며 Google 심사 완료일을 보장하지 않는다. 계정/서명/패키지 문제가 풀리지 않으면 비공개 테스트 시작일도 뒤로 이동한다.

| 단계 | 담당 | 작업 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- | --- |

개인 계정 중 **2023-11-13 이후 생성 계정**에는 최소 12명·14일 연속 요건이 적용된다. 먼저 계정 유형과 Console 표시를 확인한다. 내부 테스트와 비공개 테스트를 구분하고 실제 참여·피드백 기록도 준비한다. [개인 계정 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)

등록비는 일회성 US$25이며 계정 유형에 따른 신원·기기 검증을 진행한다. [Play Console 등록](https://support.google.com/googleplay/android-developer/answer/6112435?hl=en)

**첫 공개 출시는 5%→20% 같은 단계적 배포가 불가능하다.** 선택 국가의 첫 출시로 범위를 제어한다. 비율별 단계적 배포는 후속 업데이트에서 사용한다. [첫 출시와 업데이트](https://support.google.com/googleplay/android-developer/answer/9859348?hl=en)

## 4. Android 출시 후보의 검증 항목

- `make check` → `make test-e2e-v2`로 공통 코드 확인. 이후 `VERSION_CODE=<미사용 증가값> make android-aab`; `VERSION_CODE=1`을 무조건 재사용하지 않는다. 서명 설정은 아직 없다. unsigned QA 번들과 임시 측정 APK만 만들었으며 출시 AAB는 미검증이다.
- bundletool/Console에서 최종 다운로드 크기·지원 기기·SDK·서명 확인. 16KB 페이지 환경과 네이티브 의존성 점검 포함. 소스가 TS여도 SDK의 네이티브 라이브러리를 빠뜨리지 않는다. [16KB 지원 가이드](https://developer.android.com/guide/practices/page-sizes)
- **권고 기기 조합**: 실제 중저사양 Android 기기 + 최신 Android 기기, 지원 하한 API 24 에뮬레이터, 16KB 에뮬레이터. 기기/OS/해상도·결과를 기록하며 확보 못한 조합은 미검증으로 남긴다.
- Play에서 설치한 앱으로 첫 실행, 한/영, 세로/가로, 하드웨어 뒤로가기, 긴 전투, 백그라운드→복귀, 앱 강제 종료→이어하기, 업데이트 후 세이브 유지 확인.
- 비행기 모드로 기본 런 시작·저장·재접속, 리소스 로딩, AI fallback 확인. 네트워크 복귀 후 클라우드 충돌·일일 기록 재전송 확인. 로그아웃이 기기 진행을 지우지 않는지 확인.
- Google 로그인·취소·로그아웃·계정 전환; Play app-signing 인증서 적용. 업로드 키와 Play 서명 키를 혼동하지 않는다.
- 알림 기본 off/허용/거부/다국어, Crashlytics 전송 토글, 개발자용 화면 노출 여부, 구매 상품이 없는 무료 버전에서 비활성 업셀 노출 여부 확인.
- 계정 삭제와 AI 신고는 전용 QA 계정에서 실행한다. 실제 사용자 데이터를 검증용으로 삭제하지 않는다. Android에 로그인 보호 기능이 있으므로 “모든 기능 접근 제한 없음”이라고 신고하지 않는다.

**11-05 로컬 기기 검증:** debug APK를 별도 API 36 16KB 에뮬레이터에 설치했다. 오프라인 새 런→전투, Android 뒤로가기→일시정지, 백그라운드 복귀, 프로세스 종료 후 동일 저장 데이터와 전투 복구를 확인했다. 안정된 세로 화면은 412×863 CSS px이며 `outputs/android-native-qa/settled-combat-device.png`에 보관했다. 후속 수정에서 SystemBars를 native 여백 처리로 바꿔 시작 경고를 없앴고, 최종 빌드 재실행 3회·가로/세로 전환에서 해당 경고와 미처리 JS 예외가 없었다. 가로 뒤로가기와 회전 후 저장 유지도 확인했다. API 24의 기본 WebView 53에서는 빈 화면이 재현돼, 현재 빌드 기준인 WebView 111을 실행 조건으로 명시하고 한/영 업데이트 안내와 Google Play 링크를 넣었다. 후속 검증에서는 별도 AOSP API 24와 개발용 WebView 111에서 오프라인 새 게임→전투, 뒤로가기→일시정지, 백그라운드 복귀·강제 종료 후 동일 저장 복원을 확인했다. [후보 검증 기록](2026-11-05-android-candidate-verification.md)에 환경과 화면 증거를 남겼다. Play 배포 WebView·실기기·로그인·결제 QA는 미검증이다. 자세한 명령·아티팩트는 `docs/PROGRESS_LOG.md` 최신 항목을 따른다.

**팀 출시 기준(정책 수치 아님)**: 알려진 시작 불가·세이브 손실·결제/삭제 오류 0건, 위 핵심 경로 통과, 미해결 고심각도 pre-launch report 항목 0건. 재미 평가는 사람의 의견으로 별도 기록한다. 웹 E2E만으로 Android 출시 승인을 대체하지 않는다.

11-05 코드 대조 결과는 [데이터·심사 접근 점검표](2026-11-05-play-data-and-review-audit.md)에 정리했다. 기존 Data safety 답안은 이 표로 대체한다. 알림 off와 FCM 식별자 수집 중단은 다르고, AI 신고는 새 신고가 들어올 때만 90일 초과 자료를 지우며, 계정 삭제 응답은 Firebase 정보 삭제 실패를 별도로 표시할 수 있다. D1은 자동 등록 기본 차단·끄기 시 토큰 삭제 요청을 구현하고 오프라인 기기 검사를 통과했다. 실제 토큰 삭제·갱신과 오프라인 대기 요청의 재연결·재시작 정리를 검증했고, 설정에서 대기 중인 켜기를 취소하는 동작도 통과했다. [연결 검증 기록](2026-11-05-push-connected-acceptance.md)에 수정 전 실패와 수정 후 결과를 남겼다. 이전 debug 설치본의 알림 on/off 두 상태에서 업데이트 후 저장·프로필·설정 보존을 확인했다. 기존 off 상태의 대기 큐는 재연결 30초 동안 토큰을 만들지 않고 남아 있었으며, 명시적으로 다시 켠 뒤 정리되었다. 키보드를 연 채 가로로 회전할 때 입력창이 가려지는 문제도 수정하고 실제 Android IME에서 회전·다시 열기·뒤로가기를 검증했다. [업데이트·키보드 검증 기록](2026-11-05-android-upgrade-keyboard-qa.md)에 범위와 결과를 남겼다. 실기기·Play 서명·한글 조합 검증은 남아 있다. FCM 대기 요청 정리와 키보드 수정까지 포함해 미서명 QA AAB를 다시 빌드했다. 최대 기본 다운로드 추정치는 368,390,479바이트이며, [업데이트·키보드 검증 기록](2026-11-05-android-upgrade-keyboard-qa.md)에 최신 해시·서명 상태를 기록했다. 끄기 후에도 이전 구독 정리를 위해 연결 중 등록 정보가 일시적으로 생성·전송될 수 있음을 정책 초안에 반영했다. D1–D8을 해결한 뒤 최종 답안을 작성한다. D3 독립 정리 명령은 격리 DB에서 검증했지만 운영 정기 실행은 아직 연결하지 않았다. D2/D4/D6의 한·영 정책과 설정 안내는 로컬 초안을 수정했다. 공개 페이지 배포·연락처·실제 계정 삭제 검증이 남아 있으므로 G2를 완료 처리하지 않는다.

**데이터 위치·백업 후속 점검:** 운영 DB 연결은 Neon PostgreSQL이며 주소에 표시된 지역은 `us-east-1`이다. Cloud Run의 `us-central1`과 구분한다. 현재 Gemini 설정은 `global`로 해석되며, 해당 모델·지역의 요청/응답 로깅 설정은 없음(기본 비활성)을 확인했다. 이것만으로 AI 무보관이나 모든 처리의 미국 한정을 주장하지 않는다. Neon의 실제 복구 이력 기간·스냅샷·외부 백업·복원 후 삭제 요청 반영은 아직 확인이 필요하다. [D7 점검 기록](2026-11-05-data-locations-backup-audit.md)에 증거와 다음 확인 절차를 남겼다.

**오류 보고 후속 점검:** 오프라인 Android에서 설정·재시작 유지와 기기의 미전송 보고서 보관을 확인했다. 끄기는 미전송 파일 삭제와 다르며, 네이티브 자동 전송 중단 설정은 다음 앱 실행에 적용된다. 다시 켜면 기기에 남은 보고서가 전송될 수 있음을 한·영 설정·정책 초안에 반영했다. [오류 보고 검증 기록](2026-11-05-crash-offline-acceptance.md)에 최신 미서명 AAB(최대 기본 다운로드 추정 368,390,744바이트), 실제 화면·SDK 검증과 한계를 기록했다. 테스트 보고서는 전송하지 않았다.

**스토어 이미지 후속 점검(11-06):** [검증 기록](2026-11-06-store-listing-audit.md)에 최신 디버그 APK 해시와 연결한 실제 Android 캡처 10장, 선정한 8장과 그래픽 3개를 정리했다. 캐릭터 화면 2장은 표시 이상 재확인 전까지 보류한다. 브라우저 테스트 화면은 별도 자료로 구분했고 아이콘 RGBA 형식과 원본 보존 검사를 확인했다. 최종 Play 서명 후보 대조와 Console 수락은 남아 있으며 G2를 완료 처리하지 않는다.

## 6. Signal+는 별도 출시 게이트

무료 버전의 안정성과 실제 AI 비용을 확인한 뒤 착수한다. 과거 월 순이익·환율·AI 단가 표는 시나리오이며 현재 수익성 증거가 아니다. 월 ₩3,900과 무료 $0.30/Plus $1.50 허용량, 일 $20·월 Vertex 차단 정책의 상호작용을 재계산한다. 유료 이용자가 전역 차단으로 서비스를 못 쓰는 경우의 안내·처리 기준을 마련한다.

1. 오너가 사업 형태·국가별 판매 요건·판매자 프로필을 확인한다. Google은 한국 사업자의 유료 앱/IAP 배포에 사업자등록·통신판매업 정보 등을 요구한다. 모든 개인에게 동일한 신고 의무라고 단정하지 않고 본인 상황을 확인한다. [한국 개발자 정보](https://support.google.com/googleplay/android-developer/answer/3255733?hl=en)
2. `signal_plus_monthly`, 월 자동 갱신 기본 요금제, 지역 가격·세금·구독 혜택·취소 링크 확정. 서비스 계정의 Play 권한은 필요한 앱 범위로 오너가 부여한다.
3. Play 설치 라이선스 테스터로 구매 승인·pending·실패·중복 요청·복원·계정 불일치·갱신·취소·만료·환불/철회를 확인한다. 서버 `/plan`의 상태와 일치해야 한다. fake API 통과로 완료 처리하지 않는다.
4. 현재 서버는 저장한 만료 시각 이후에 재조회하고 RTDN이 없다. **환불/철회 후 만료 전 권한이 남는 경로를 해결하고 검증한 뒤 판매한다.** RTDN 또는 동등한 재검증 설계·지연 기준을 정하고, 구매 기록 및 삭제 정책과 함께 검증한다.
5. Billing 8은 현재 소스에 있다. 출시 시 지원 버전과 최종 manifest를 다시 확인한다. [Billing 지원 기한](https://developer.android.com/google/play/billing/deprecation-faq)
6. 상품·결제 검증, 고지와 지원 준비 완료 → 오너가 판매 활성화 → 별도 업데이트 및 실제 판매 상태 확인. Play Console 상품 활성화와 코드 배포를 구분한다.

## 7. 첫 재개 때 확인할 다섯 가지

1. Console 계정이 있는지, 개인/조직인지, 생성일과 검증 상태.
2. 개발자 공개 명의·지원 이메일, 초기 출시 국가, 무료 우선안 채택 여부.
3. 업로드 키와 백업의 보관 위치(비밀번호를 문서/채팅에 적지 않음).
4. 비공개 테스트 참여자 확보 상황과 담당 연락 방식. 초대 메시지는 오너 승인 후 보낸다.
5. 출시 후보 기기 검증을 수행할 실기기와 human fun verdict 담당자.

11-05 추가 검증: Android 크기 검사는 bundletool 방식으로 수정했고, 상품 조회 중·없음·실패 시 구매 버튼을 숨기며 구역을 유료 혜택으로 설명하던 문구도 고쳤다. 한/영 8개 UI 사례 통과. 다음 준비는 서명·계정·연락처 입력을 확보한 뒤 Play 설치본의 기기·리뷰어 접근·삭제 검증이다. 계정 결제·서명 키 생성·권한 확대·업로드·게시·유료 상품 활성화는 이 문서 작성으로 수행되지 않았다.
