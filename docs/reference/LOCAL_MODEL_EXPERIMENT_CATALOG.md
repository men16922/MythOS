# 로컬 모델 실험 카탈로그

성격: **이식 가능한 레퍼런스.** 이 문서는 특정 리포지토리에 의존하지 않습니다. 다른 프로젝트로 그대로 복사해 쓸 수 있도록 작성했습니다.
대상: 로컬 GPU(소비자급 12~24GB 또는 Apple Silicon 통합메모리)로 LLM·이미지·영상 모델 실험을 설계하는 사람.
최초 작성 2026-09-02.

---

## 0. 이 카탈로그의 전제

**로컬 모델 실험은 "무엇을 만들까"로 시작하면 대부분 실패합니다.** 만드는 것은 재미있지만 결론이 남지 않기 때문입니다. 이 카탈로그는 다른 질문으로 시작합니다:

> **무엇을 재면, 남들이 모르는 답이 나오는가.**

여기 있는 실험들의 공통점은 새 모델을 만들지 않는다는 것입니다. 전부 **다들 당연히 된다고 믿고 확인하지 않는 것을 확인합니다.**

## 1. 실험 선정 기준 — 자기 실험을 추가할 때 쓰는 필터

새 아이디어가 떠오르면 이 세 개를 통과하는지 먼저 봅니다. **하나라도 못 넘으면 실험이 아니라 취미입니다.**

### 기준 1 — 결정론적 지표가 있는가

지표가 주관적이면 **측정한 것이 대상이 아니라 판정자의 노이즈**입니다. LLM-as-judge는 동일 입력에 대해 반복 채점하면 흔들립니다(측정 사례: 5점 척도에서 **약 1점**). 그러면 1점 이하의 차이는 원리적으로 주장할 수 없습니다.

**해법은 판정자를 개선하는 게 아니라 판정이 필요 없는 과제를 고르는 것입니다:**

| 모달리티 | 쓸 수 있는 결정론적 지표 |
|---|---|
| 텍스트 | JSON 스키마 유효율 · 코드 실행 통과율 · 산술 정확도 · 파싱 성공률 · 토큰 수 · 지연 |
| 이미지 | 임베딩 코사인 유사도 · **OCR 정확도**(텍스트 렌더링 모델) · 생성 시간 · 로드 여부(이진) |
| 영상 | **없음.** 시간적 일관성은 아직 객관 지표가 없음 → V-1 참조 |

### 기준 2 — 음성 결과도 결과인가

*"효과 없었다"*, *"차이가 노이즈에 묻혔다"* 가 발표 가능한 결론이어야 합니다. 아니라면 그 실험은 **처음부터 특정 답을 원하고 있는 것**이고, 그러면 무의식적으로 그 답이 나옵니다.

좋은 형태: *"A가 B보다 나은가?"* → 어느 쪽이든 결론
나쁜 형태: *"A가 얼마나 좋은지 보여주자"* → 결론이 이미 정해짐

### 기준 3 — 하룻밤에 끝나는가

12GB / 48GB급 로컬 장비에서 **한 번의 격자가 8~12시간 안에** 끝나야 합니다. 그래야 하루에 한 번 반복할 수 있고, 반복 가능해야 잘못된 설계를 고칠 수 있습니다. 일주일짜리 실험은 설계 오류를 일주일 뒤에 발견합니다.

## 2. 모달리티별 실험 난이도

| | 결정론적 지표 확보 | 실험 난이도 | 한 줄 |
|---|---|---|---|
| **텍스트** | **어렵다** — 우회 과제를 설계해야 함 | 높음 | 실험 시간의 절반이 과제 설계에 감 |
| **이미지** | **쉽다** — 임베딩·OCR·시간이 그냥 있음 | **낮음** | LLM 실험에서 제일 어려운 부분이 공짜 |
| **영상** | **미해결** | 최고 | 지표를 만드는 것이 첫 실험 |

**직관과 반대입니다.** 이미지·영상이 "더 어려워 보이는" 것은 생성이 무겁기 때문이지, 실험 설계가 어렵기 때문이 아닙니다. 오히려 이미지 쪽이 결론이 빨리 납니다.

## 3. 실험 카드

각 카드는 동일한 양식입니다. **`음성 결과일 때`** 항목이 비어 있으면 그 실험은 기준 2를 못 넘은 것입니다.

### L-1. LLM Judge 노이즈 바닥 측정 프로토콜

| | |
|---|---|
| **주제** | LLM-as-judge는 **동일한 입력에** 얼마나 흔들리는가. N점 차이를 주장하려면 표본이 몇 개 필요한가 |
| **가설** | 온도 0에서도 흔들린다. 그리고 흔들림 폭이 측정하려는 효과와 같은 크기다 |
| **지표** | 동일 입력 반복 채점의 표준편차 (완전 결정론적 — 입력이 바이트 단위로 같으므로) |
| **격자** | 고정 샘플 20개 × judge 3종(로컬 8B / 로컬 32B / API) × 온도 3단 × **반복 10회** = 1,800 판정 |
| **하드웨어** | 48GB 통합메모리 또는 24GB VRAM. 하룻밤 |
| **산출물** | *"이 루브릭·이 judge에서 1점 차이를 유의하게 주장하려면 표본 K개"* 표 |
| **음성 결과일 때** | "노이즈가 0.1점이다" → 훌륭한 결과. 그 judge는 신뢰 가능하고 그 사실 자체가 값 |
| **함정** | **루브릭 자체가 프롬프트에 들어갑니다.** 루브릭을 한 글자 고치면 judge를 바꾼 것과 같은 효과가 납니다. 루브릭의 해시를 기록하지 않으면 나중에 드리프트를 귀속할 수 없습니다 |

> **왜 이게 다른 모든 실험의 전제인가**: 품질 축이 걸린 실험은 전부 "차이가 노이즈보다 큰가"를 물어야 합니다. 노이즈 바닥을 모르면 그 질문에 답할 수 없고, **모르는 채로 진행하면 노이즈를 재게 됩니다.**

### L-2. 양자화 품질 절벽 — 판정자 없이 찾기

| | |
|---|---|
| **주제** | 양자화 단계별 품질 저하 곡선이 **어디서 절벽으로 바뀌는가** |
| **설계 핵심** | **LLM judge를 아예 쓰지 않습니다.** 정답이 있는 과제만: JSON 스키마 유효율 · 코드 실행 통과율 · 산술 정확도 |
| **가설** | 가중치만 4bit는 무해. KV 캐시까지 내리면 급락 (민감도 순서: weights < activations < KV < attention) |
| **격자** | 모델 1종(8B급) × 양자화 5단계(bf16 / int8 / AWQ-4 / GGUF Q4 / Q3) × 과제 3종 × 500문항 |
| **하드웨어** | 12GB로 충분 |
| **산출물** | 절벽의 **좌표**. 문헌은 민감도 순서만 말하고 위치는 안 줌 |
| **음성 결과일 때** | "Q3까지 아무 차이 없다" → 훨씬 공격적인 양자화가 가능하다는 실용적 결론 |
| **함정** | 양자화 방식이 다르면 **모델도 다른** 경우가 많습니다(같은 이름의 다른 빌드). 같은 원본에서 파생된 것인지 확인하지 않으면 모델 비교를 양자화 비교로 착각합니다 |

### L-3. 샘플러 파라미터가 실제로 하는 일

| | |
|---|---|
| **주제** | `repeat_penalty` / `top_p` / `top_k` / `num_predict` / `num_ctx` 가 엔진별로 **정말 전달되고, 정말 출력을 바꾸는가** |
| **가설** | 상당수가 조용히 버려진다. 특히 OpenAI 호환 엔드포인트는 네이티브 API 형식의 옵션을 **에러 없이 무시**한다 |
| **★ 설계 핵심** | **전달 여부(A)와 효과(B)를 분리 측정합니다.** `num_predict=5`를 보내고 691자가 나오면 안 먹은 것 — 이렇게 **극단값으로 이진 판정**을 만듭니다 |
| **격자** | 엔진 4종(Ollama compat / Ollama native / vLLM / llama.cpp 또는 MLX) × 파라미터 6종 × 극단값 |
| **하드웨어** | 12GB. 몇 시간 |
| **산출물** | 엔진별 **"실제로 먹는 파라미터" 매트릭스** + 조용히 무시되는 것 목록 |
| **음성 결과일 때** | "전부 정상 전달된다" → 그것도 문서화 가치가 있는 음성 결과 |
| **실화** | 어떤 파이프라인에서 6개 옵션이 `extra_body`로 전달되고 있었고, **한 번도 적용된 적이 없었습니다.** 형식을 고친 뒤 출력 열화율이 44% → 0%로 바뀌었습니다. 아무도 확인하지 않는 클래스입니다 |

### L-4. 작은 모델의 충분성 경계 — 구조화 추출

| | |
|---|---|
| **주제** | 자유 텍스트 → JSON 구조화에서 **모델 크기별 유효율이 어디서 포화되는가** |
| **가설** | 생각보다 훨씬 작은 모델에서 포화된다 (구조화는 지능보다 형식 준수 문제) |
| **지표** | 스키마 유효율 · 필드 정확도. 전부 결정론적 |
| **격자** | 0.5B / 1.5B / 3B / 8B / 14B × 같은 과제 × 500샘플 |
| **하드웨어** | 12GB (14B는 양자화 필요) |
| **산출물** | 포화 곡선. *"이 과제엔 NB면 충분하고 그 위는 낭비"* |
| **음성 결과일 때** | "14B에서도 포화 안 된다" → 이 과제는 생각보다 어렵다는 결론 |
| **확장** | 가장 작은 모델을 그 과제에 파인튜닝해서 한 단계 큰 모델을 이기는지. 지표가 결정론적이라 판정 문제가 없고, 이기면 **쓸 수 있는 물건**이 남습니다 |

### L-5. 저자원 언어가 먼저 무너지는가

| | |
|---|---|
| **주제** | 양자화·모델 축소가 **비영어권에서 더 빨리 붕괴**하는가 |
| **가설** | 그렇다 (토크나이저 효율이 나쁜 언어일수록 취약) — 널리 믿어지지만 좌표가 없음 |
| **★ 지표 트릭** | **해당 언어로 된 JSON 스키마 유효율.** 언어는 비영어인데 정답은 기계 판정 가능 |
| **격자** | L-2와 같은 격자를 **언어 쌍으로**. 같은 내용, 두 언어 |
| **하드웨어** | 12GB |
| **산출물** | *"언어 X는 N bit에서 영어보다 M% 먼저 무너진다"* 또는 **"차이 없다"** |
| **음성 결과일 때** | "차이 없다"가 오히려 유용 — 저자원 언어 제품에서 양자화를 주저할 이유가 없어짐 |
| **참고 측정** | 문자수÷4 휴리스틱과 영어권 토크나이저(cl100k)는 한국어 토큰을 **약 44% 과다계산**합니다. 토큰 예산 계산에 그대로 쓰면 안 됩니다 |

### I-1. LoRA 무성 실패 매트릭스 ★ 착수 1순위

| | |
|---|---|
| **주제** | 학습 플랫폼 × 추론 스택 조합별로 LoRA가 **실제로 로드되는가** |
| **왜 아무도 안 했나** | **에러 없이 실패**하기 때문입니다. 키 네이밍이 안 맞으면 추론 스택은 아무것도 적용하지 않고, 그림은 멀쩡히 나옵니다 — **베이스 모델 출력이**. 사용자는 "품질이 별로"라고 읽지 "안 로드됐다"고 읽지 않습니다 |
| **지표** | **완벽하게 이진**: 베이스 출력과 임베딩 유사도가 1.0이면 안 로드된 것. 판정 여지 없음 |
| **격자** | 트레이너 3종 × 추론 스택 3종 × 베이스 모델 3종 = **27칸**. 각 칸에 동일한 LoRA 하나 |
| **하드웨어** | 12GB. 하룻밤 |
| **산출물** | *"이 조합은 조용히 아무것도 안 한다"* 매트릭스 + 변환이 필요한 지점 목록 |
| **음성 결과일 때** | "전부 정상 로드된다" → 그 자체로 안심 자료. 그리고 이식성 리스크가 없다는 결론 |
| **부수 가치** | LoRA를 납품하는 사업이라면 이 테스트가 그대로 **출하 검수**입니다. 아무것도 안 하는 파일을 보내면 고객은 클레임 대신 재계약을 안 합니다 |

### I-2. LoRA는 몇 장부터 효과가 있나 — 포화점과 과적합점

| | |
|---|---|
| **주제** | 학습 이미지 수 대비 **정체성 유사도가 어디서 포화되고, 어디서 과적합이 시작되는가** |
| **가설** | 커뮤니티 통념("10~30장")보다 이르게 포화하고, 그보다 훨씬 이르게 프롬프트 순응도가 꺾인다 |
| **지표** | 정체성 = 임베딩 코사인 / 순응도 = VQA 이진 판정 또는 CLIP score |
| **격자** | 5 / 10 / 20 / 40 / 80 / 160장 × 동일 스텝 수 × 평가 프롬프트 50개 |
| **하드웨어** | 12GB 학습 + 평가는 어디서든 |
| **★ 진짜 산출물** | 포화점이 아니라 **두 곡선의 교차점**. 유사도는 계속 오르는데 순응도가 꺾이는 지점이 실무적 최적 |
| **음성 결과일 때** | "160장까지 계속 좋아진다" → 데이터가 많을수록 좋다는 결론(그리고 대규모 데이터셋의 값이 확인됨) |
| **함정** | 장수를 늘리면서 **스텝 수를 같이 늘리면** 두 변수를 섞은 것입니다. 스텝을 고정하거나, 에폭 고정과 스텝 고정을 둘 다 재야 합니다 |

### I-3. 양자화 × 이미지 품질 — 판정자 없이

| | |
|---|---|
| **주제** | FP16 → FP8 → INT8 → NF4 에서 **그림이 얼마나 달라지는가** |
| **★ 지표 트릭 두 개** | ① 같은 시드·같은 프롬프트의 **FP16 출력을 기준점**으로 두고 임베딩 거리 측정 ② **텍스트 렌더링이 되는 모델이면 OCR로 채점** — 완전 객관 |
| **가설** | 텍스트 렌더링이 그림보다 **먼저** 무너진다 (세밀한 구조라서) |
| **격자** | 모델 1종 × 정밀도 4단계 × 프롬프트 100개(텍스트 포함 50 / 미포함 50) |
| **하드웨어** | 12GB |
| **산출물** | 절벽 위치 + **무엇이 먼저 무너지는가** 순서 |
| **음성 결과일 때** | "NF4에서도 구분 불가" → 저사양 배포가 열림 |
| **함정** | 같은 시드가 같은 그림을 보장하는지 먼저 확인해야 합니다. 정밀도가 바뀌면 시드가 같아도 궤적이 갈라지는 구현이 있습니다 — **그러면 기준점 설계가 무효**입니다 |

### I-4. 커뮤니티 속도 주장 검증

| | |
|---|---|
| **주제** | *"기법 X가 N배 빠르다"* 는 커뮤니티 주장을 **단일변수 통제로** 재기 |
| **가설** | 조건에 따라 부호가 바뀐다 |
| **지표** | 시간은 그냥 재고, 품질은 I-3의 임베딩 거리 |
| **격자** | 기법 on/off × 해상도 3단 × 배치 3단 × 스텝 수 2단 |
| **하드웨어** | 12GB |
| **산출물** | *"조건 X에서 N배, 조건 Y에서 손해"* — 커뮤니티가 구조적으로 만들 수 없는 형태 |
| **음성 결과일 때** | "주장이 전 구간에서 사실이다" → 드물지만 그러면 채택하면 됩니다 |
| **근거가 되는 실측** | 어떤 추측 디코딩 기법이 한 조건에서 **+199%**, 다른 조건에서 **−53.7%** 였습니다. 그리고 손해가 난 지점의 **수용률은 100.0%** 였습니다 — 추측이 하나도 안 틀렸는데 손해가 났습니다. **조건 없는 "몇 배"는 정보가 아닙니다** |

### I-5. LoRA 강도 트레이드오프 곡선

| | |
|---|---|
| **주제** | LoRA weight 0.0 → 1.5 스윕에서 **정체성(오름)과 프롬프트 순응도(내림)의 교차점** |
| **가설** | 통념인 "0.8" 이 LoRA마다 다르다 |
| **지표** | 정체성 = 임베딩 유사도 / 순응도 = VQA 이진 판정 |
| **격자** | weight 7단계 × LoRA 5종(캐릭터/스타일/컨셉 혼합) × 프롬프트 30개 |
| **산출물** | 최적 weight의 위치와 **분산**. 분산이 크면 "0.8 쓰세요"는 틀린 조언 |
| **음성 결과일 때** | "전부 0.8 근처" → 통념이 맞았다는 확인. 그것도 결과 |

### V-1. 영상 — 시간적 일관성을 잴 수 있는가 (메타 실험)

| | |
|---|---|
| **주제** | 영상 품질에 **judge 없는 지표를 만들 수 있는가** 자체를 묻는 실험 |
| **후보 지표** | 프레임 간 임베딩 거리의 **분산**(튀는 프레임 탐지) · 광학 흐름 불연속 · 캐릭터 정체성의 프레임별 표준편차 |
| **검증법** | 사람이 "깨졌다"고 판정한 클립 집합과 지표 순위가 **일치하는지**. 순위 상관으로 확인 |
| **하드웨어** | 생성은 무거우나 평가는 가벼움. 클립 50개를 미리 만들어 두고 지표만 반복 |
| **산출물** | 지표가 생기면 **영상 실험 전체가 열립니다** |
| **음성 결과일 때** | "어떤 지표도 사람 판정과 상관이 없다" → *"영상 품질은 아직 자동으로 못 잰다"* 가 결론. **이것도 발표 가치가 있는 결과이고**, 영상 실험에 뛰어들지 않을 근거가 됩니다 |

> **영상 카드가 하나뿐인 이유**: 아이디어가 없어서가 아니라 **지표가 없으면 나머지 영상 실험이 전부 주관 판정으로 무너지기 때문**입니다. V-1이 문지기입니다.

### X-1. 판정 비용은 모달리티마다 정말 다른가 (크로스모달)

| | |
|---|---|
| **주제** | *"이미지 판정이 텍스트 판정보다 훨씬 싸다"* 는 통념을 실제로 측정 |
| **계획** | 같은 사람이 ① 텍스트 A/B 50쌍 ② 이미지 A/B 50쌍을 판정. **소요 시간과 재판정 일치율을 둘 다** 기록 |
| **지표** | 판정당 초 · 동일 쌍 재판정 시 일치율(= 사람 judge의 노이즈 바닥) |
| **산출물** | 두 모달리티의 **인간 노이즈 바닥**과 "N배 싸다"의 실제 배수 |
| **음성 결과일 때** | "이미지도 사람 판정이 흔들린다" → 이미지 품질 주장도 표본이 필요하다는 결론 |
| **왜 중요한가** | *"품질을 잴 수 있는 모달리티에서만 로컬 모델로 갈 수 있다"* 는 판단 전체의 근거입니다. L-1과 **같은 하네스로 돌아갑니다** — 사실상 한 실험의 두 팔 |

## 4. 공통 실행 규율

카탈로그의 어느 실험을 하든 지켜야 하는 것들입니다. **이걸 안 지키면 측정한 값이 무엇의 값인지 알 수 없게 됩니다.**

1. **단일 변수만 바꾼다.** 매니페스트에 변경 항목을 한 줄로 적고, 그 한 줄만 다른 두 실행을 비교합니다. 두 개를 같이 바꾸면 결과의 귀속이 불가능합니다.
2. **노이즈 바닥을 먼저 잰다.** 아무것도 바꾸지 않고 같은 실행을 N회 반복해서 분산을 봅니다. **그 분산보다 작은 차이는 이후 어떤 표에도 쓰지 않습니다.**
3. **모든 리포트에 스탬프를 찍는다.** 실행 시각 · 모델과 버전 · 커밋 해시 · 전체 인자 · **프롬프트/루브릭의 해시**. 프롬프트는 입력의 일부이므로, 기록하지 않으면 나중에 드리프트를 귀속할 수 없습니다.
4. **음성 결과를 같은 비중으로 보고한다.** "효과 없음"을 빼고 보고하면, 여러 실험을 쌓았을 때 남는 것은 우연히 좋게 나온 것들뿐입니다.
5. **기동 로그를 파일로 남긴다.** 엔진이 시작할 때 출력하는 메모리 예산·동시성 한계는 설정이 바뀌면 **조용히** 달라집니다. 에러 없이 천장만 낮아지는 종류의 변화라 로그 없이는 못 잡습니다.
6. **합산하지 않는다.** 워크로드나 조건을 섞어 평균 내면 설명력이 0이 되는 경우가 흔합니다. 조건별로 갈라 재고, 갈랐을 때 부호가 바뀌는지 봅니다.

## 5. 이미 검증된 규칙 — 실험 설계에 미리 반영할 것

다른 실험에서 실측으로 확인된 것들입니다. 다시 검증할 필요는 없고, **설계 단계에서 전제로 쓰면 됩니다.**

| # | 규칙 | 근거 |
|---|---|---|
| 1 | **수용률·정확도는 필요조건이지 충분조건이 아니다** | 추측 디코딩 수용률 100%인 지점에서 처리량 −53.7%. 원인은 정확도가 아니라 **한 스텝의 예산에 여유가 없어서** 다른 요청의 실행 기회를 뺏은 것 |
| 2 | **자원을 먹고 들어가는 최적화는 출발부터 진다** | 보조 모델을 같이 올리면 KV 예산이 −42.2%가 되어 **어느 조건에서도** 이득이 없었음. 반대로 남는 자리만 쓰는 기법은 이득이 남 |
| 3 | **설정이 전달됐는가와 효과가 있는가는 별개 측정이다** | 옵션 6개가 잘못된 형식으로 전송돼 **한 번도 적용된 적이 없었음**. 에러도 경고도 없었음 |
| 4 | **손계산은 아키텍처를 반영해도 로그로 확인해야 한다** | GQA를 무시한 공식이 6배 틀림. 반영해도 실행 설정에 따라 실측값이 또 달라짐 |
| 5 | **틀린 수정이 맞아 보일 수 있다** | 어떤 설정을 올렸더니 **리플레이에서 3/3 복구**됐는데, 새 실행에서는 여전히 실패했음. 그 프롬프트들은 **실패했던 바로 그 설정에서** 리플레이 시 성공했음 — 즉 수정은 무효였고 리플레이가 조건을 재현하지 못한 것. **스탬프가 찍힌 리포트가 이걸 잡았습니다** |
| 6 | **판정자의 노이즈는 측정 대상과 같은 크기일 수 있다** | 바이트 단위로 동일한 표본을 재채점했더니 5점 척도에서 약 1점이 움직였음 |
| 7 | **캐시·재사용의 이득은 서버 설정이 아니라 워크로드의 성질** | 프리픽스가 공유되는 워크로드에서는 8배, 공유가 없으면 켜든 끄든 1% 이내 |

**규칙 5가 가장 중요합니다.** 나머지는 특정 기법에 대한 것이지만, 5번은 **실험 절차 자체에 대한 것**이라 어느 실험에서든 발생합니다.

## 6. 착수 순서

```
I-1  LoRA 무성 실패 매트릭스      ← 1~2주. 이진 결과, 하룻밤, 아무도 안 함
  ↓
L-3  샘플러 파라미터 매트릭스      ← 1~2주. 같은 성격: "다들 확인 안 하는 것"
  ↓
L-1 + X-1  판정 노이즈 (양 모달리티) ← 3주. 본편. 다른 전부의 전제
  ↓
I-2 / I-3 / L-2 / L-4 / L-5        ← 위가 끝나야 "차이가 진짜"라고 말할 수 있음
  ↓
V-1                                ← 영상은 여기서 처음
```

**I-1을 먼저 하는 이유**: 결과가 이진이라 해석 여지가 없고, 하룻밤이면 끝나고, 표 하나가 그대로 산출물입니다. **하네스가 제대로 도는지 검증하기에 가장 좋은 대상**이기도 합니다 — 답을 이미 아는 칸(정상 조합)이 섞여 있으므로, 그 칸이 틀리면 실험이 아니라 하네스가 고장 난 것입니다.

**L-1/X-1이 본편인 이유**: 결과가 나오면 **다른 모든 품질 실험의 전제가 확정**되고, 동시에 방법론 자산이 됩니다. *"우리 판정자는 동일 입력에서 N점 흔들린다, 그러므로 N점 이하의 차이는 주장하지 않는다"* 를 수치로 말할 수 있는 사람은 드뭅니다.

마지막 두 절이 이 양식의 핵심입니다. **없으면 그 리포트는 주장이지 측정이 아닙니다.**

## 8. 이 카탈로그의 한계

- **n=1 환경.** 여기 실험들은 대개 GPU 1장·모델 소수·조작자 1인입니다. 나오는 것은 **규칙과 방법**이지 절대 수치가 아닙니다. 다른 하드웨어로 숫자를 옮기지 마십시오.
- **규모가 없습니다.** 처리량·오토스케일링·라우팅 연구는 합성 부하 없이는 불가능합니다. 여기 카탈로그는 **형태와 조건**을 다루지 **양**을 다루지 않습니다.
- **영상은 아직 카드가 하나뿐입니다.** 지표 문제(V-1)가 풀리기 전까지는 늘릴 수 없습니다.
- **§5의 규칙들은 특정 환경의 실측에서 왔습니다.** 규칙의 방향은 이전되지만 배수는 이전되지 않습니다.
