## 요약

빈 응답을 냈던 프롬프트 4개를 그대로 재생. `num_ctx` 하나만 16384 → 32768로 바꿨을 때 **0/4** 이 텍스트를 생성했습니다.

## 측정

### 동일 프롬프트, num_ctx만 변경

| # | 프롬프트 토큰 | 프롬프트+num_predict vs num_ctx | num_ctx=16384 (현행) | num_ctx=32768 |
|---|---|---|---|---|
| 0 | 7245 | 9293 <= 16384 | 1301 tok / **766 자** | 1363 tok / **696 자** |
| 1 | 7458 | 9506 <= 16384 | 1434 tok / **857 자** | 1476 tok / **814 자** |
| 2 | 7615 | 9663 <= 16384 | 1689 tok / **871 자** | 1336 tok / **923 자** |
| 3 | 7440 | 9488 <= 16384 | 1264 tok / **795 자** | 1572 tok / **953 자** |

> 샘플러(temperature/top_p/top_k/repeat_penalty/num_predict)는 두 팔에서 동일합니다.

## 발견

1. **[measured]** 빈 응답은 컨텍스트 창 부족에서 온다 — 0/4이 창을 넓히자 회복됐다.
   - 근거: 동일 프롬프트·동일 샘플러, `num_ctx` 16384→32768 단일 변수.
2. **[measured]** 현행 설정은 프롬프트와 요청 생성량의 합이 창을 넘는다.
   - 근거: 프롬프트 7245–7615 토큰 + num_predict 2048 > num_ctx 16384.
3. **[indicative]** 이 실패는 fallback이 덮으므로 플레이 화면과 장면 저장소만 보면 보이지 않는다.
   - 근거: 드라이버는 같은 턴들을 성공으로 보고했고, 트레이스에서만 빈 응답이 드러났다.
